# 数智伴学｜教师网页原型第一轮修改任务清单

**需求依据**：`数智伴学_开发需求清单.docx`（摘自《数智伴学商业计划书（完整版 · 11.18 修订版）》）。表中章节号沿用摘录，便于回查。首错定位、证据不足可留待判断、教师追问与改判是原计划要求；单击直达、按钮文案、保存回执、下一份导航和投影尺寸是本轮新增的交互或验收细节。

**本轮目标**：第一次使用的老师不听讲解，也能打开班级 → 找到待核对作答 → 看清第一处错步 → 决定是否当面问一句 → 保存并查看下一份；回头知道去哪里找记录。90 秒只是演示举例，不设为操作时限。

**交付边界**：以**教师电脑端网页**为主，第一轮不同时改桌面端。首期限定一个教材版本的一元一次方程单元，学生在线下口答或纸笔作答，不设学生账号、在线答题或自动评分。本清单均为待办。

**版本口径**：A 是 **V0.1 交互原型的第一个开发切片**，不是完整 V0.1。完整原型仍须用同组模拟数据串联「导入校正 → 课前问题总览 → 课中追问与分层提示 → 教师审核发布 → 课后验证记录」，并附演示脚本、页面说明和模拟数据清单（3.6、5.5 表15）。

## A. 第一轮｜先做通作答核对与追问

| 勾选 | 页面 / 功能 | 要改的内容 | 完成标准 |
|---|---|---|---|
| [ ] A1 | 首页／课前总览 | 当前班级下显示本次作业、待核对数量和下一份待核对作答，主按钮为「查看待核对作答」。新建班级、AI 设置等保留为次级入口。（原计划：4.2 表6；单击直达为本轮设计） | 选定班级后点一次直达作答，不绕学生名单；区分「尚未导入作答」和「本次作答已核对完」。待核对数按当前作业计算，与「查看下一份」使用同一队列。 |
| [ ] A2 | 作答核对／首处错步 | 分开显示题目、逐行学生原文与标准解，完整标准解默认折叠。用「首处不等价」和下划线标错步，附简短数学对照。固定合成案例允许用标明来源的预置错步；若第一轮就验收新导入作答的自动定位，须把 B2 中的限定题型离线规则提前。（原计划：5.1 表9、5.2–5.4） | 对 `3(x−2)=12 → 3x−2=12`，老师能看到学生原文保留了 `−2`，正确展开是 `3x−6`。不从这一行推断学生为什么这样写。正确作答不标错；仅有最终答案显示「缺少步骤」，不猜错在哪一行；超出核验范围转人工。预置演示不宣称已实现通用定位。 |
| [ ] A3 | 作答核对／保存错步 | 分开记录「观察到的错步」「可能原因」「教师判断」。提供「保存错步，原因待判断」；「待核对／已核对」描述处理进度，「原因待判断／教师已判断」描述原因判断，两者独立。（原计划：4.2 表6、3.4） | 保存、关闭并重开后，仍显示原错步和「已核对 · 原因待判断」。该份退出待核对队列但仍可找回；可计入原题错误数，不计入已确认错因。正确或缺测作答不因点确认而生成错题。 |
| [ ] A4 | 作答核对／当面追问 | 本轮典型案例默认显示「可以这样问学生：你当时是怎么展开这个括号的？」只放「记录学生回答」「暂时跳过」，不另建学生页面。复用已有问句和原话记录能力，将追问关联到当前作答及其版本，不以已生成正式错题为前提。原计划的已审短题选项仍保留在产品范围。（原计划：5.1 表9、5.3、5.5 表16） | 「暂时跳过」只跳过提问，不自动保存、不跳页、不产生回答记录。老师可保存待判断，课堂上再回到同一份补记原话。跳过不等于学生拒答；没有新增依据时，原因仍待判断。 |
| [ ] A5 | 保存结果／返回并找回 | 同屏呈现学生原话、支持或削弱解释的依据和教师判断；允许采纳、改判或保留待判断。成功时显示保存到哪个班级与作业，再提供「查看下一份」。（原计划：3.2、4.4、5.5 表16；回执和队列导航为本轮设计） | 「查看下一份」按固定顺序留在当前作业；最后一份保存后明确收尾。返回保留原班级和作业，能从「原因待判断」找回记录。改判后旧原因不再作为当前结论；保存失败留在当前页并保留输入。列表与详情一致。 |
| [ ] A6 | 视觉／投影 | 每屏只突出一个主要动作；公式比记录编号醒目；错步用下划线和文字标记，不只靠颜色。本项是本轮界面验收细化。 | 在 1366×768 和实际投影设备上，典型案例首屏可见错步和主动作，无需横向滚动；长作答仍可展开查看。 |
| [ ] A7 | 合成演示／独立试用 | 至少准备一份值得追问的作答（原计划案例 A）和一份只有最终答案的作答（案例 C），统一标「合成演示数据」。演示无需现场选文件、配模型或等网络；重置只影响合成数据。（原计划：5.2–5.5；重置与独立走查为本轮设计） | 请一位未参与开发的老师不听讲解，独立完成「找到作答、指出错步、跳过或补记回答、找回记录」。记录停顿、误点和需要解释的位置，再改一轮。不按耗时判通过。 |

**执行顺序**：先定首轮只验固定案例还是也验新导入作答，再用合成数据串通 **A2 → A3 → A4 → A5**，包括保存后关闭重开；然后接 A1，最后做 A6、A7。回归覆盖正确作答、仅有答案、跳过后补记、改判、保存失败和最后一份收尾。若第一轮保留覆盖导入，原作答变化后旧判断至少要退出当前视图及统计，新作答回待核对；完整版本追溯留 B2。若尚未调整 CSV 缺测口径，「只有答案」用合成数据验收，不把它算作真实导入已支持。

## B. 后续开发｜补齐完整 V0.1 展示与 V0.2 可运行 MVP

先补完 V0.1 的五环节合成演示。以下业务能力可分批开发，但必须按 **V0.2 验收口径**交付，不能以预置案例代替真实功能。

| 勾选 | 修改项 | 完成标准 |
|---|---|---|
| [ ] B1 | 导入校正与班级统计 | 支持真实 CSV 导入与校验、手工补录、去重和冲突提示；关键公式确认后再进入正式分析。区分未参加、参加但缺步骤、老师尚未录入；按作业显示应交、有效、缺测和待核对，可回看明细。原题正误与错因分布分别统计。 |
| [ ] B2 | 确定性错步定位、错因库检索与更正重审 | 一元一次方程范围内按相邻等式核验、输出首个不等价步骤，超范围转人工。候选来自已审错因库，最多 3 条，每条附支持、反驳和待补信息。原作答、关键证据或资源版本改变后，旧结论退出当前统计、可追溯，新版本回待审；用「已确认的错误作答改为正确解」验收。 |
| [ ] B3 | 追问记录、资源双审核与个体确认 | 从已审追问库选用适用短问并记录回答；通用追问、提示和练习分别记录数学审核与教学审核。任课教师的个体判断及发布范围单独记录。未审资源与失效结论不进入发布。 |
| [ ] B4 | 纸笔任务导出与独立后测 | 可预览、导出不附答案的纸笔验证题，记录实际给过的提示级别和学生是否自行修正。即时新题与 7–14 天延迟新题关联原记录，原题订正不算迁移；新题结果分独立完成、提示后完成、未完成和缺测。 |
| [ ] B5 | 校内数据、权限与导出 | 个体作答不进入生成式模型调用；在服务端按任课关系逐次校验查看、查询和导出。默认导出不含姓名，检查小样本识别风险；用「预览后撤权，再点导出不产生文件」验收。 |
| [ ] B6 | 操作日志、删除与备份恢复 | 查看、修改、导出、删除保留必要审计至少六个月；能处理正式记录与备份，验证恢复旧备份不使已删记录重新可见。 |
| [ ] B7 | V0.2 独立案例报告与部署材料 | 按题族隔离并封存至少 100 条独立案例，原则上 60 错／20 对／20 证据不足。报告确认覆盖率、标签精确率、正确例误报率及失败案例。原计划建议门槛为覆盖率 ≥70%、精确率 ≥90%、正确例误报率 ≤5%，证据不足不强判；附部署说明和关键权限、审核用例结果。 |

## C. V1.0｜真实试点与扩大试用

- [ ] **试点前**：通过 V0.2 关键权限和审核门槛，取得学校授权并完成告知同意；在约定班级和单元内试用，保留教师反馈及数据处理记录。
- [ ] **扩大试用前**：至少 2 名教师各做 5 组可比配对任务，报告实际耗时；演示跑通、诊断质量、教师耗时和教学效果分别报告。

**暂缓**：学生端账号与在线答题、复杂 OCR、自由生成追问、多学科、装饰性大屏。保留现有 CSV 导入、备份、原文引用与教师记录能力，不为演示重写。

**实现定位**：网页班级入口在 `src/web/app.js`，本轮需补网页作答核对页和队列入口；已有共享 API 在 `src/app/api.py`。桌面 `src/desktop/ui.py` 的 `AnswerReviewDialog`、`FollowupWindow` 作为交互参考，不列为本轮交付。共享业务重点在 `src/app/answer_review.py`、`src/app/followup.py`、`src/app/answers.py`、`src/app/stats.py`；已有追问不能直接照搬「先确认错题」的依赖。详细反例见历史归档 `归档/数智伴学_现有成果评审.md`。
