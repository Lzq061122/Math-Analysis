# 演示脚本｜第一轮（作答核对与追问）

**给谁用**：面向评委、校长、听课老师的现场演示。按下面的顺序讲，五幕串起来是一件事：**课前看总览 → 看清首处错步 → 决定要不要追问 → 保存 → 回头能找回。**
**不要照着背**：台词是提议，讲的人按自己的话说更自然；关键是「点什么、屏幕应显示什么」这两列不能乱。

> **90 秒只是举例**：完整讲一遍大约是这个量级，但本项目**不设操作时限，也不按耗时判通过**。老师第一次用慢一点是正常的，要记录的是哪里停顿、哪里会错点，而不是秒表。

---

## 0. 开场前 30 秒的准备（不上屏）

| 检查项 | 做法 | 为什么 |
| --- | --- | --- |
| 只开一个浏览器窗口 | 关掉其它标签，地址停在班级总览 | 演示时切页最容易卡在「找哪个窗口」 |
| 数据已就位 | 已在演示班级点过「载入合成数据」（幂等，点两次也是 4 份） | 不需要现场选文件、配模型、等网络 |
| 屏幕比例 | 浏览器 1366×768 一屏能看见错步与主按钮 | A6 的验收口径，投影前先确认 |
| 断网也能演 | 合成数据全部本地生成 | 现场网络不可靠时不必解释 |
| 讲清数据性质 | 第一句话就说「这是合成演示数据」 | 避免被误解成真实学生数据 |

**开场第一句（建议）**：「这一屏的班级、学生、作答都是合成数据，专门用来演示流程的；合成数据可以一键重置，真实导入的作答一条都不会动。」

## 第一幕｜课前总览：老师先知道今天要核几份

| 说什么 | 点什么 | 屏幕应显示什么 |
| --- | --- | --- |
| 「老师打开班级，第一眼看到的不是名单，是今天要核多少份。」 | 进入班级（默认停在作答核对总览） | 作业名 `9月第2次作业`；应交 4 份、待核对 4 份、已核对 0；缺测 0 |
| 「系统先替老师排好顺序，给一句不带结论的提示。」 | 不点，只读提示行 | `学生甲 · 第 1 题 · 去括号：是规则没掌握，还是这次漏写？` |
| 「主按钮只有一个：查看待核对作答。」 | 单击 **查看待核对作答** | 直接进到案例 A 的作答核对页；不经过学生名单、不经过错题列表 |

**不在这幕做的事**：不点「新建班级」、不点「AI 设置」、不讲导入。这两个入口本轮只是次级入口。

---

## 第二幕｜首处错步：只指出哪里不等价，不说学生为什么错

| 说什么 | 点什么 | 屏幕应显示什么 |
| --- | --- | --- |
| 「学生原文逐行列出来；第 2 行加了虚线和文字标记。」 | 不点，指屏幕 | `3(x-2)=12` → **`3x-2=12`（首处不等价，`-2` 有下划线）** → `x=14/3` |
| 「对照很轻：展开后应该是 3x-6，括号外的 3 也要乘 -2。」 | 不点 | 数学对照一行，字号明显大于记录编号 |
| 「到这里系统就停住了——它不说学生为什么这么写。」 | 不点 | 固定说明：「这里只记录观察到的不等价，不推断学生为什么这样写。」 |
| 「这行是预置演示，不代表我们已经有通用定位能力。」 | 不点 | 标记「预置演示 · 不代表已实现通用定位」；数据来源「合成演示数据」 |
| （可选）「标准解默认收起来，不抢注意力。」 | 点开/收起标准解 | 展开出现 `3x-6=12；3x=18；x=6`，再收起 |

**如果被追问「是不是 AI 看出来的」**：答「不是。这一份的首错是预置条目，本轮演示的是『把错步摆清楚、把原因留给老师判断』这条流程；对任意新作答自动定位属于下一阶段（B2）的规则引擎。」

---

## 第三幕｜追问：问一句，或者跳过

| 说什么 | 点什么 | 屏幕应显示什么 |
| --- | --- | --- |
| 「老师会想当面问一句：你当时是怎么展开这个括号的？」 | 不点 | 提示句出现，两个按钮：**记录学生回答** / **暂时跳过** |
| 「先演跳过——跳过只是不问，不会替老师下结论。」 | 点 **暂时跳过** | 页面不跳、不保存、不产生空的回答记录；状态仍是「原因待判断」 |
| 「课堂上问了，就把学生原话记在这份作答上。」 | 在输入框敲入（或演示预置文本）`2 只要乘 y 就好了。` → 点 **记录学生回答** | 同屏出现学生原话；追追问挂在当前作答及其版本上，不依赖「已生成正式错题」 |

**不要说的话**：不说「学生拒答了」——跳过≠拒答；不说「系统据此确定原因是……」。

---

## 第四幕｜保存：回执要说清存到哪，并给下一份

| 说什么 | 点什么 | 屏幕应显示什么 |
| --- | --- | --- |
| 「三个区块分开：观察到的错步 / 可能原因 / 教师判断。」 | 不点 | 区块标题齐全；两个标签分开显示：「待核对」与「原因待判断」 |
| 「可能原因最多三条，每条都有支持、反驳、待补；没有一条被写成定论。」 | 指屏幕 | `E-DIST-01` 只把系数乘以括号里的第一项 / `E-DIST-02` 系数与符号处理偏差 / `E-WRITE-01` 书写遗漏；各自三类证据 |
| 「老师现在只做一件事：把错步存下来，原因留到课堂上判断。」 | 单击 **保存错步，原因待判断** | 同屏四样：学生原话、依据、「已保存到：七年级 1 班 · 9月第2次作业」、状态「已核对 · 原因待判断」 |
| 「保存是留痕，不是改分数：原题错误数 +1，已确认错因还是 0。」 | （在统计或回执说明处指一下） | 两个口径分开呈现，不合并成一个「错」 |
| 「下一位。」 | 单击 **查看下一份** | 进到案例 B（`5x-3=2x+6`）；队列按固定顺序，不回头乱跳 |

**可选插播（各 15 秒，视时间）**

- 案例 C（`4(x-1)=8` 只写 `x=1`）：讲「只有最终答案 → 显示『缺少步骤』，不猜错在哪一行，保存后不生成错题」。
- 对照作答（`2(x+3)=10` 全对）：讲「正确作答不标错」。
- 最后一份保存后：讲「本次作业已核对完」的收尾，不给空白的「下一份」。

---

## 第五幕｜找回：返回还能找到，改判留痕

| 说什么 | 点什么 | 屏幕应显示什么 |
| --- | --- | --- |
| 「一节课上完，老师想回头看看还有哪些『原因待判断』。」 | 进 **记录**（待判断筛选） | 列表里有刚保存的那份：学生甲、第 1 题、观察到的错步 `3x-2=12`、保存时间、作业批次 |
| 「列表和详情必须说同一件事。」 | 点开这条记录 | 详情里的错步、学生原话与列表一致 |
| （可选）「判断可以改；旧原因不作为当前结论，但历史留着。」 | 选另一条候选 → 保存 | 状态变「教师已判断」，旧原因进历史，不再当当前结论 |
| 「返回不会把老师丢回首页。」 | 返回 | 仍在这个班级、这个作业批次 |

---

## 收尾话术（建议原文）

「今天就演了这一条线：课前知道要核几份，看清第一处错步，决定问还是不问，存下来，回头找得到。
要说明的是三件事：第一，今天的学生和作答都是合成数据，可以一键重置；第二，这一份的首错是预置演示，还不代表我们能对任意作答自动定位；第三，系统只记录观察到的不等价，原因由老师判断——这也是我们不把『已核对』和『已判断原因』合成一个标签的原因。」

## 演示中容易被问到的问题

| 提问 | 回答口径 |
| --- | --- |
| 换一个新班级还行吗？ | 可以重置后重演；重置只删合成数据，真实导入的作答一条不动，重置接口会返回保留的条数。 |
| 真实学生的作答能自动找出错步吗？ | 本轮不承诺。通用定位在下一阶段，现在的演示是预置结果。 |
| 断网还能演吗？ | 能。合成数据本地生成，不联网、不读外部文件、不调模型。 |
| 为什么两个状态标签？ | 一个是「这份处理了没有」，一个是「原因判断了没有」，两件事，混在一起会让老师误以为系统已经替她下了结论。 |
| 追问是不是必须生成错题才能问？ | 不是。追问挂在作答及其版本上，不以生成正式错题为前提。 |
| 跳过会记录什么？ | 什么都不记：不发请求、不跳页、不产生空回答记录。 |

## 不要说的话（现场红线）

- 不说「系统已经能自动定位任意错步」。
- 不说「第一轮五个页面已经全部跑通」，也不说「V0.2 阶段已经通过验收」——这两件事分别以独立走查记录和验收结果为准。
- 不说「AI 判断原因是……」，只说「候选来自预置条目，最终由老师判断」。
- 不说「90 秒就能做完」当作指标；只当举例。
- 不把合成班级说成真实班级，不展示任何真实姓名或学号。
