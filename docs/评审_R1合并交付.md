## §2 数据一致性（stats / overview / 错题数三处）

- `stats.answer_check.expected` == `overview.assignment.total` == 库里该批真实作答数（=3）：**同源**；t9-B1
- `manual_verified`、`cause_not_applicable` 在 `stats` 与 `overview.counts` 同名同值；t9-B2
- 撤回后 `stats.cause_decided` 归零，`checked` 与 `overview.counts.checks_current` 相等（撤回真的退出统计）；t9-B3
- 纯 SQL 复算（不经过 API）：`cause_decided` == 库里「当前版本且 decided」份数；t9-11c

**发现（需整改·低）批名撞演示批次名时口径分裂**：把一条**真实导入**的作答放进批名 `【合成演示】不计入真实作业` 后
（`probe_batchname.py` 实测）：
```
resolve_batch(无参) = 【合成演示】不计入真实作业
overview.assignment = {total: 0, pending: 0, synthetic: true}
overview.assignments = [评审作业(3)]          ← 该批次整条不列
stats.answer_check   = {batch: 【合成演示】…, expected: 1}
```
即：这份真实作答在总览/队列里**不可见**（0 份），但被统计按 1 份计数 → 老师会以为这批没作业。
可达性低（批名须恰好等于两个演示批名之一），但一旦发生是静默丢展示。建议 `resolve_batch` 只认真实批次时排除演示批名，
或 overview 对「演示批名 + 含真实行」明确提示。
