## 0. 一句话摘要（给并行开发的三分钟版）

1. **四维独立**：作答 / 核验 / 错因 / 评分四条轴各自有状态枚举与合法迁移，任一条的变动不连带改写另外三条（除非 §5 的失效规则显式规定）。
2. **一切按版本**：核验结论、追问证据、评分都挂 `answers.fingerprint`；指纹一变，旧结论**自动退出当前视图**（不写清理逻辑），历史行保留。
3. **一切按作用域**：统计与成绩一律按 `(class_id, batch)`；同名不同班、同班同名都不合并、不改名。
4. **评分只有 `confirmed` 算数**：草稿不计入任何正式指标；不完整成绩不进平均分；缺分母显示「暂无/无法计算」，绝不拿 0 冒充。
5. **真实学生作答永不外发**：R2 新增流程全部本地规则，账号级 AI 开关对它们无效（只对 R1 既有的错题照片分析生效）。
6. **公共层只有一个**：常量/状态机/失效规则/统计口径都在 `src/app/r2_contract.py`（纯函数、无副作用），其它模块 import 它，不许复制粘贴。

## 2. §2.2 数据关联标识

**所有跨模块引用只用下面这些标识，不许自创「批次 ID 猜名字」「按学生姓名匹配」这类关联。**

| 标识 | 定义 | 唯一性 | 由谁写 | 说明 |
|---|---|---|---|---|
| `class_id` | 班级主键 | `classes.id` | 原版 | 所有查询的第一层收口 |
| `student_id` | 学生主键 | `students.id` | 原版 | 不按姓名匹配（同名是常态） |
| `answers.id`（`answer_id`） | 一份作答（一个学生 × 一道题 × 一个批次） | 主键 | 导入/补录 | 核验、追问、评分、图片都挂在它上面 |
| `answers.record_key` | 老师给的稳定编号 | 班内唯一（`idx_answers_class_record`） | 导入 | 识别重复导入；**不是**跨班唯一 |
| `answers.fingerprint`（`answer_version`） | 作答内容指纹 | 内容变则变 | 原版 | **唯一的「当前结论」闸门**：`answer_version = fingerprint` 才算当前 |
| `answers.batch` + `class_id` | 批次作用域 | 二元组 | 导入 | 见 §3；同名不同班各算各的 |
| `answer_checks.id`（`check_id`） | 一条教师核验结论 | 主键 | R1 | 当前结论由 §4 核验维判定 |
| `answer_followups.id` | 一条追问原话 | 主键 | R1 | 证据快照 `evidence_snapshot` 一起读 |
| `answer_images.id` | 一张作答图片 | 主键；`(answer_id, seq)` 唯一 | R2-01 | 多图按 `seq` 排序展示 |
| `answer_scores.id` | 一条评分 | 主键；`(answer_id, question_no, answer_version)` 在 `draft/confirmed` 内唯一 | R2-02 | 见 §3.4 |
| `mistakes.answer_id` | 错题 ← 作答 的幂等键 | 局部唯一（非空时） | R1-16 | 同一份作答最多一条错题 |
| `teaching_resources.resource_key` | 资源的跨版本独立 ID | 全库唯一 | R2-05 | 版本号 `version` 与它组合定位到具体版本 |
| `teaching_tasks.id` | 教学任务 | 主键 | R2-05 | 引用资源时记 `resource_versions`（key→version） |
| `hint_usages.id` | 一次提示使用记录 | 主键 | R2-05 | 关联 `answer_id` / `task_id`（都可空） |

**关联规则（硬）**：
- 跨班一律不可见：所有 R2 查询必须带 `class_id`；`JOIN answers a ON a.id=... AND a.class_id=...`（R1 的教训：只按 `answer_id` JOIN 会跨班串味）。
- 「当前版本」只有一个判据：`r2_contract.is_current_version(answer_version, fingerprint)`。撤回行 `answer_version=''` 永远不是当前版本。
- 演示数据识别走 `source` 内容判据（`source='合成演示'`），**不按批名猜**（`r2_contract.include_in_formal_stats`）。

## 3. §2.3 批次配置（`assignment_batches`）

### 3.1 一份批次配置长什么样

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `class_id` | int | 所属班级 | 必填 |
| `batch` | text | 批次名，与 `answers.batch` **同一个字符串** | 必填（`missing_batch` 校验） |
| `name` | text | 展示名称（默认等于 `batch`） | `= batch` |
| `occurred_on` | text | 作业日期 `YYYY-MM-DD`，可空 | `''` |
| `expected_students` | json | **应作答学生名单** `[{"key","name","code"}]`（`key` = 学号优先，否则姓名） | `[]` |
| `expected_questions` | json | **应作答题号** `["1","2",...]`（一律字符串） | `[]` |
| `scored_questions` | json | **应评分题范围**（必须是 `expected_questions` 的子集） | `[]` = 全评 |
| `full_scores` | json | **各题满分** `{"1":10,...}` | `{}` |
| `rubric` | json | **各题评分标准原文** `{"1":"...",...}` | `{}` |
| `rubric_version` | text | 评分标准版本串 | `''` |
| `config_state` | text | `configured` / `unconfigured` | `unconfigured` |
| `origin` | text | `legacy` / `import` / `manual` | `legacy` |

**校验错误码**（`r2_contract.BATCH_CONFIG_CODES`，R2-01 预览与 R2-02 录入共用同一套中文提示）：

`missing_batch`、`bad_date`、`bad_origin`、`bad_config_state`、`students_not_list`、`student_key_missing`、`student_key_duplicate`、`questions_not_list`、`question_no_duplicate`、`scored_not_in_expected`、`full_score_missing`、`full_score_invalid`、`rubric_version_missing`、`config_incomplete`

只校验「能不能据此出统计」的硬条件（应评分题在应作答范围内、满分 > 0、给标准就要给版本）。名单/题号为空是**合法**的：那是「历史批次未配置」，统计显示「暂无」而不是报错。

### 3.2 四种「没交」必须分清（派单明确要求）

| 情形 | 判定 | 记在哪 | 统计口径 |
|---|---|---|---|
| **未提交** | 应作答名单里有这个学生，但该题**没有任何记录** | 不落行（是「格子空着」） | `unsubmitted_answers`（只算应作答格子 − 有记录格子） |
| **缺测** | 有记录、但 `answers.missing=1`（请假/未测） | `answers.missing` + `missing_reason` | `missing_answers` |
| **内容不足** | 有记录、没标缺测、只有照片或没有可核验过程 | `answer_images` 有行 + 文本为空 | `insufficient_answers` |
| **有效** | 有可核验的文本/步骤 | 原版 `answers` 字段 | `valid_answers` |

判据函数（唯一实现）：`r2_contract.classify_record_state(missing, missing_reason, has_text, has_steps, image_count)` → `(state, reason_code)`。
**顺序不可颠倒**：`missing=1` 优先于内容量（R1 的缺测标记不许被「内容看起来还行」推翻）。

### 3.3 完整成绩判定

`r2_contract.score_completeness(config, confirmed_scores)`：

- 应评分题范围里**每一题**都有 `confirmed` 成绩 → `complete=True`，`total=Σ分数`；
- 缺任何一题 → `complete=False`、`missing=[题号]`、`total=None`；
- 批次没有配置应评分题 → `reason="batch_unscored"`，界面显示「暂无」。

**只有完整成绩**进「平均分 / 完整成绩人数 / 评分覆盖率」。理由：拿半份成绩拉平均等于编数字。

### 3.4 评分行（`answer_scores`）与步骤扣分

| 字段 | 含义 |
|---|---|
| `answer_id` / `question_no` / `batch` / `class_id` / `student_id` | 定位（冗余存 `batch` 是为了免 JOIN 就能按批次过滤） |
| `full_score` | **抄批次配置的满分**（同批次同题统一，禁止前端另传） |
| `score` | 分数（0 ≤ 分 ≤ 满分，≤2 位小数；无依据可留空） |
| `state` | `unscored` / `draft` / `confirmed` / `invalidated` |
| `answer_version` | 打分时的 `answers.fingerprint`（内容一变，这条自动失效） |
| `rubric_version` | 打分时的标准版本（标准一变，这条自动失效） |
| `steps_json` | 步骤扣分快照（与 `score_step_deductions` 同期写入，便于追溯） |
| `scored_by` / `scored_at` / `confirmed_by` / `confirmed_at` | 谁在什么时候打分/确认 |
| `revision_reason` | 改已确认分的理由（必填，改动留痕） |
| `invalidated_at` / `invalidated_reason` / `invalidated_by` | 失效留痕（不删行） |
| `history` | JSON 数组：每次改分/撤回/失效追加一条 |

唯一性：`idx_scores_answer_version`（局部唯一）——同一份作答同一题同一版本只保留一条 `draft/confirmed` 行；`invalidated` 行不受限制（留历史）。

`score_step_deductions`：`score_id` + `step_index`（可空，自由扣分项）+ `label` + `deduction` + `note`。
一致性闸门：`r2_contract.step_deductions_consistent(full, score, deductions)` 必须 `满分 − Σ扣分 = 分数`，否则**拒绝保存**（不改库）。

颜色/文案：`unscored`「未评分」、`draft`「草稿（不计入统计）」、`confirmed`「已确认」、`invalidated`「已失效（需重评）」。

## 4. §2.4 四维独立状态

### 4.1 四维与枚举

| 维 | 含义 | 枚举（`r2_contract.STATES`） |
|---|---|---|
| ① 作答 `answer` | 这份作答有没有、算不算可核验内容 | `unsubmitted` 未提交 / `missing` 缺测 / `insufficient` 内容不足 / `valid` 有效 |
| ② 核验 `verify` | 数学核验结论是否**当前有效** | `unverified` 未核验 / `verified_rule` 已核验（规则） / `verified_manual` 已核验（人工） / `verified_preset` 已核验（演示预置） / `stale` 旧版本（已失效） |
| ③ 错因 `cause` | 与 R1 `cause_state` 逐字一致 | `undecided` 原因待判断 / `decided` 教师已判断 / `not_applicable` 无需判断 |
| ④ 评分 `score` | R2 新增 | `unscored` 未评分 / `draft` 草稿 / `confirmed` 已确认 / `invalidated` 已失效 |

辅助枚举（不属于四维，但同样只许从这里取字符串）：
`RESOURCE_STATES`：`draft` 草稿 / `pending_review` 待审核 / `published` 已发布 / `disabled` 停用；
`TASK_STATES`：`draft` 草稿 / `scheduled` 已安排 / `completed` 已完成 / `cancelled` 已取消；
`TASK_REVIEW_STATES`：`ok` 依据有效 / `needs_review` 依据已变，待复核；
`HINT_LEVELS`：`P1` 关键步骤提示 / `P2` 规则提示 / `P3` 局部示例提示（默认 `P1 → P2 → P3`）。

**独立性举例（必须成立）**：撤回错因（③ → `undecided`）后，② 仍是 `verified_rule`、④ 仍是 `confirmed`，成绩照旧计入统计。

### 4.2 合法迁移（`STATE_TRANSITIONS`）

| 维 | 允许迁移 |
|---|---|
| ① 作答 | `unsubmitted → {unsubmitted, missing, insufficient, valid}`；`missing → {missing, insufficient, valid}`；`insufficient → {insufficient, valid}`；`valid → {valid, insufficient}` |
| ② 核验 | `unverified → {unverified, verified_rule, verified_manual, verified_preset}`；`verified_* → {自身, 其他 verified_*, unverified, stale}`；`stale → {stale, verified_*, unverified}` |
| ③ 错因 | 三态两两可迁（含自迁移） |
| ④ 评分 | `unscored → {unscored, draft, confirmed}`；`draft → {draft, confirmed, unscored, invalidated}`；`confirmed → {confirmed, draft, unscored, invalidated}`；`invalidated → {invalidated, draft, unscored}` |

非法迁移用 `r2_contract.transition_state(dim, from, to)` → 抛 `ValueError`（中文消息），`transition_allowed()` 做纯判定。

### 4.3 R1 → R2 状态映射（`LEGACY_STATE_MAP`）

| 维 | R1 依据 | R1 取值 | R2 状态 |
|---|---|---|---|
| 作答 | `answers.missing` | `0` / `1` | `valid`（再按内容细分）/ `missing` |
| 作答 | 无记录（名单里有） | — | `unsubmitted` |
| 核验 | `answer_checks.answer_version` vs `answers.fingerprint` | 相等且 `verify_source=rule` / `manual` / `preset` | `verified_rule` / `verified_manual` / `verified_preset` |
| 核验 | 同上 | 不等（含撤回后置空） | `stale` |
| 核验 | 无 `answer_checks` 行 | — | `unverified` |
| 错因 | `answer_checks.cause_state` | `undecided` / `decided` / `not_applicable` | 逐字一致 |
| 错因来源 | `answer_checks.cause_source` | `none` / `preset` / `teacher` / `legacy` | **不改**（是来源，不是状态） |
| 评分 | 1.8.1/R1 无评分 | — | `unscored` |

**R1 语义一律不改**（`r2_contract.R1_UNCHANGED_FIELDS`）：`answer_checks.answer_version`、`cause_state`、`cause_source`、`verify_source`、`manual_state`、`locate_detail`、`basis_note`、`invalidated_at`、`answers.missing`、`missing_reason`、`fingerprint`、`mistakes.answer_id`、`users.ai_individual_allowed`。

## 5. §2.5 更新与失效规则（11 条）

规则以**数据**形式登记在 `r2_contract.INVALIDATION_RULES`，执行入口是纯函数 `apply_event(trigger, state, event, rules=None)` → `{"state", "actions", "rules"}`。落库由调用方按 `actions` 执行（动作名是契约，不含 SQL）。

| # | 触发词 | 规则 | 失效/保留 | 执行者 | 反向自证（去掉这道闸，哪条断言必红） |
|---|---|---|---|---|---|
| `R2-INV-01` | `answer_content_changed` | 作答内容变化（重导覆盖 / 单条补录 / 校正） | 核验→`stale`、错因→`undecided`、评分→`invalidated`；追问证据标 `answer_updated`；历史行保留 | `answer_check.update_content()` / 导入覆盖 | 指纹比较改成恒不等 → 「同指纹重导不失效」必红 |
| `R2-INV-02` | `check_retracted` | 撤回核验结论 | 核验→`unverified`（`answer_version` 置空 + `invalidated_*`）、错因→`undecided`；**评分保留**；同版本不堆行 | `answer_check._retract()` | 撤回行 `answer_version` 仍填原值 → 唯一索引/当前结论查询必红 |
| `R2-INV-03` | `cause_retracted` | 撤回错因判断 | 错因→`undecided` 并写 `cause_history`；核验与评分各自独立保留 | `answer_check.save()` | 撤回连带撤成绩 → 「撤 1 条错因成绩仍在」必红 |
| `R2-INV-04` | `score_saved` | 评分落库 | 只有 `confirmed` 计入正式统计；`draft` 一律排除（回显可以，统计不行） | `grading.save_score()` | 统计把 draft 算进去 → 「部分评分不计入平均」必红 |
| `R2-INV-05` | `rubric_changed` | 改评分标准 / 满分 | 该题既有成绩→`invalidated`（需重评），旧分数/扣分项/旧版本留历史 | `grading.update_rubric()` | 只改标准正文不改 `rubric_version` → 「改标准旧成绩失效」必红 |
| `R2-INV-06` | `score_retracted` | 撤回成绩 | 评分→`unscored`，退出平均分/得分率/覆盖率/完整成绩；历史保留 | `grading.retract_score()` | 撤回后仍按 `confirmed` 计数 → 「撤回成绩退出正式统计」必红 |
| `R2-INV-07` | （无触发词，校验类） | 步骤扣分与总分一致性 | `满分 − Σ扣分 ≠ 分数` → **拒绝保存**（不改库）并提示差额 | `grading.save_score()` 前置校验 | 去掉一致性校验 → 「步骤分一致性拦截」必红 |
| `R2-INV-08` | `resource_version_changed` | 教学资源新版本 / 停用 | 引用旧版本的推荐/提示/任务标「依据已变，待复核」，不静默换成新版本，不删旧引用 | `teaching_resources.publish_version()` | 引用改成「总读最新」→ 「历史版本与任务引用可追溯」必红 |
| `R2-INV-09` | `task_basis_changed` | 教学任务依据变化 | 只打 `review_state=needs_review`；任务状态不动、不自动改派、不自动完成 | `teaching_resources.mark_task_review()` | 依据变化自动置 `cancelled` → 「任务历史/状态可追溯」必红 |
| `R2-INV-10` | `batch_config_changed` | 批次配置变化（题号范围/满分） | 只重算口径与完整成绩判定；已有成绩不因题号范围变化而失效（满分/标准变化的走 05） | `db.save_batch_config()` | 把「完整成绩」判成「至少一题有分」 → 完整成绩断言必红 |
| `R2-INV-11` | `batch_scope_changed` | 批次与演示数据归属 | 统计按 `(class_id, batch)` 重算；同名历史批次不改名/不合并；演示数据不进正式统计 | `db.ensure_r2_schema()` / `r2_stats` 查询条件 | 去掉 `source<>'合成演示'` 或按批名合并 → 演示隔离断言必红 |

**写库三条总纪律**：
1. **不删行**：失效、撤回、重导一律「保留旧行 + 标版本/状态」，不物理删除。
2. **不静默纠正**：能判错就 4xx/拒绝并说清原因，不改写老师输入。
3. **响应即真相**：接口返回的四个状态就是库里的状态，界面只按返回值渲染。

## 9. 数据模型与迁移方案（1.8.1 / R1 → 1.9.0）

### 9.1 为什么不升 `SCHEMA_VERSION`

`src/desktop/data_dir.py::_db_problem()` 用 `version != SCHEMA_VERSION` 判旧库「结构不兼容」并**拒绝打开**。1.8.1/R1 的库写的是 `"4"`；若 R2 升成 `"5"`，老师双击新版会先被挡在门外，迁移根本没机会跑。
所以：`SCHEMA_VERSION` **保持 "4"**，R2 结构就绪由 `r2_schema_ready()` 单独判定；R2 库对 1.8.1 客户端仍读作 "4"，因此**可回退**（旧客户端能打开，只是看不到 R2 页面）。

### 9.2 新增 9 张表（`db.R2_DDL`）

| 表 | 用途 | 关键索引 |
|---|---|---|
| `assignment_batches` | 批次配置（§3） | 唯一 `(class_id, batch)`；`(class_id, occurred_on)` |
| `answer_images` | 作答多图 | 唯一 `(answer_id, seq)`、唯一 `(answer_id, file_path)`；`student_id`、`class_id` |
| `answer_scores` | 教师评分 | 局部唯一 `(answer_id, question_no, answer_version) WHERE state IN ('draft','confirmed')`；`(class_id, batch, question_no)` |
| `score_step_deductions` | 步骤扣分项 | `score_id`；局部唯一 `(score_id, step_index)` |
| `teaching_resources` | 教学资源（五类统一结构） | 唯一 `resource_key`；`(kind, status)`、`knowledge_point`、`cause_code` |
| `teaching_resource_versions` | 资源版本 | 唯一 `(resource_key, version)` |
| `teaching_resource_reviews` | 双审核（数学/教学） | 唯一 `(resource_key, version, review_kind, reviewer)` |
| `teaching_tasks` | 教学任务 | `(class_id, status)`、`student_id` |
| `hint_usages` | 三级提示使用记录 | `(class_id, created_at)`、`answer_id`、`task_id`、`student_id` |

**不做预留表**：以上 9 张表的每个字段都在 R2-01/02/03/04/05 的派单里有明确用途；没有任何「将来可能要用」的空表或空列。

### 9.3 迁移步骤（`MIGRATION_STEPS`）

```
1. 只读检查 r2_schema_ready()：就绪 → 直接返回 None（一个字节都不写）
2. 一致性备份 → app.db.bak-<时间戳>-<随机>（失败删残片并抛 MigrationError）
3. BEGIN IMMEDIATE → 建 9 张表与索引（全部 CREATE ... IF NOT EXISTS）
4. 登记历史批次：SELECT DISTINCT class_id, batch FROM answers WHERE batch<>''
   → 插 assignment_batches（origin=legacy, config_state=unconfigured）；已存在跳过
   → 绝不 UPDATE answers.batch（同名历史批次维持原归属）
5. COMMIT → 复核 r2_schema_ready()，不就绪抛 MigrationError（原库已备份，可回退）
6. 不 DROP/ALTER 任何 R1 既有列；不改 SCHEMA_VERSION
```

**三条硬约束**：
1. **保留原有关联**：不重建表、不删列、不改既有行；新表全部以既有主键为外键（`ON DELETE CASCADE`）。
2. **同名历史批次维持原归属**：只按 `(class_id, batch)` 登记；同名不同班各算各的；不合并、不加前缀、不改名。判据函数 `r2_contract.same_batch_scope()`。
3. **幂等**：`ensure_r2_schema()` 二次调用返回 `None`，库内行数与结构不变。

**历史批次为什么不自动补名单/满分**：把该批次自己的作答行反推成「应作答名单」，未提交数会永远是 0——那是**用数据污染口径**。因此历史批次一律 `config_state='unconfigured'`，应作答人数/未提交数/作业总分显示「暂无」，老师补配置后才出数。

**如何回滚**：迁移前都有一致性备份，覆盖回去即恢复旧结构；只想撤 R2 可 `DROP TABLE` 9 张新表与 `idx_*` 索引（R1 表一个字段都没动）。

## 10. §5.1 的 18 项统计口径（`R2_STAT_METRICS`）

| # | key | 指标 | 定义（分子 / 分母） | 缺数据 |
|---|---|---|---|---|
| 1 | `class_students` | 班级人数 | 在册学生数（`students.active=1`） | 空班 0 |
| 2 | `expected_students` | 应作答人数 | 批次 `expected_students` 去重人数 | 未配置 → 暂无 |
| 3 | `submitted_students` | 作答人数 | 该批次内**至少有一条非缺测作答**的去重学生数（只有缺测记录的学生不算；内容不足＝仅照片算作答） | 0 |
| 4 | `valid_answers` | 有效作答数 | 作答维 `valid` 的记录数 | 0 |
| 5 | `insufficient_answers` | 内容不足数 | 作答维 `insufficient`（仅照片/无过程） | 0 |
| 6 | `missing_answers` | 缺测数 | `answers.missing=1` 的记录数 | 0 |
| 7 | `unsubmitted_answers` | 未提交数 | 应作答格子数 − 有记录格子数 | 未配置 → 暂无 |
| 8 | `unverified_answers` | 未核验数 | 有效作答中 `verify=unverified` 的份数 | 0 |
| 9 | `confirmed_mistakes` | 已确认错题数 | 当前版本 `first_bad` 且 `cause=decided` 的作答数 | 0 |
| 10 | `knowledge_error_freq` | 知识点错误频次 | 按知识点分组计数（多知识点分别计、同类去重） | 空列表 |

| 12 | `cause_freq` | 错因频次 | 按 `cause_code` 分组计数（多错因分别计、同类去重） | 空列表 |

|---|---|---|
| `batch_full_score` | 满分合计（非得分） | 应评分题满分之和（`batch_full_score()`）；只用于展示「本卷多少分」，**不得**参与平均分/得分率/覆盖率/作业总分 |
| `scored_count` | 已评分数 | 单题得分率的分母配套值：该题已确认成绩的份数 |

**重复错误明细**（`R2_STAT_REPEATED_ERROR_PARTS`）：`knowledge_pairs` 知识点重复、`cause_pairs` 错因重复——两类分别计数、分别展示；合成总数只能是两者之和。

**两项排序结论**（`R2_STAT_RANKINGS`）：`class_common_issues` 班级共性问题、`student_priority_issues` 个人重点问题——按知识点频次 → 错因频次降序取前 N，附涉及学生数与示例错题。

**筛选口径**（`R2_STAT_FILTER_RULES`，派单 §5.2）：
- `class` / `batch`：作用于**全部**指标（换班级=换整套分母；批次不跨加）。
- `knowledge_point` / `cause`：默认**不**改变班级人数、作业总分、平均分、评分覆盖率；若界面要展示「筛选群体成绩」，必须单独注明范围。

**硬口径（R2-03/R2-04 不得自行改写）**：
1. 多知识点/多错因按类别分别计数，同类别内去重；
2. 成绩只用 `confirmed`；不合并不可比的满分/标准/批次；不完整成绩不进平均分；
3. 「作答人数」= 至少有一条**非缺测**记录的去重学生数：§5.6 合成数据集里若 5 条缺测全落在同一名学生身上，作答人数 = **9**（该生 5 题全缺测，只有缺测记录），不是 10；
4. 「作业总分」= **逐生**有效确认得分之和，缺题不给值（见 `assignment_total_score()`）；「满分合计」是另一项（`batch_full_score`），不是得分；
5. 「评分覆盖率」分母 = 应参与评分学生数（`scoring_students()`），不是应作答人数；
6. 缺分母显示「暂无」/「无法计算」（`STAT_EMPTY_TEXT` / `STAT_UNDEFINED_TEXT`），不拿 0 冒充；
7. 历史错题不用于推算正确率或掌握率；
8. 正式统计排除合成演示数据（`include_in_formal_stats`）。
