## 1. 实现内容与入口

### 1.1 `src/app/grading.py` 是「四维写入」的唯一入口

| 维 | 谁写 | 入口 | 说明 |
|---|---|---|---|
| ① 作答 `answer` | R1 + 本模块补失效 | `update_answer_content()` | 内容校正委托 `answer_check.update_content()`（不重写核验算法），随后按 R2-INV-01 把评分标 `invalidated` |
| ② 核验 `verify` | `answer_check.save()` | `verify_one()` / `batch_verify()` / `retry_failed()` | 逐条调用现有核验链（规则定位 + 人工核验 + 追问 + 错题同步都在 R1 那一层） |
| ③ 错因 `cause` | `answer_check.save()` | `confirm_cause()` / `retract_cause()` | 确认复用 R1 `cause_state` 语义；撤回只让 cause→undecided（R2-INV-03） |
| ④ 评分 `score` | 本模块 | `save_score()` / `confirm_score()` / `retract_score()` / `update_rubric()` | 新表 `answer_scores` + `score_step_deductions`；只有 `confirmed` 进正式统计（R2-INV-04） |

只读（不算写入，供 R2-03/R2-04/R2-05 调用）：`answer_dimensions`、`batch_rows`、`batch_progress`、
`review_progress`、`current_checks`、`current_scores`、`effective_rows`、`valid_verifications`、
`confirmed_scores`、`confirmed_causes`、`filter_options`、`score_sheet`、`scoring_progress`、
`score_completeness_of`、`mistake_of`。

### 1.2 批量核验（派单 §四.1）

- 三种范围：`scope='pending'`（全部待核验）/ `'all'`（批次内全部记录）/ `'ids'`（指定记录，按传入顺序）。
- 逐条保存 + 逐条回调（`on_result`，界面进度条数据源）+ 可取消（`cancel_check` 返回 True 即停在「未处理」）+ 可重试（`retry_failed(failed_ids)`）。
- 单条异常不阻塞整批：`verify_one()` 把 `AnswerCheckError` / `GradingError` / 其它异常都收敛成
  `{"status": "failed", "code", "message"}`，其余记录照常核验并落库。
- **重复核验不覆盖教师成果**：`verify_one()` 先看 `_protected_reasons()`（人工核验 / 已判错因 / 已确认成绩）
  → `skipped`；即使 `force=True` 也通过 `_preserve_cause_body()` 把教师已判错因原样带回要求里。

### 1.3 教师评分（派单 §四.2）

- 满分一律取 `db.load_batch_config()` + `r2_contract.full_score_of()`，前端另传满分无效（没有这个参数）。
- `r2_contract.validate_score()` 拦：非数值、<0、>满分、>2 位小数、满分未配置。
- 状态：`unscored / draft / confirmed / invalidated`，迁移一律走 `r2_contract.transition_state()`；
  `invalidated → confirmed` 按状态机经 `draft` 中转（不新建平行行，旧行留历史）。
- 草稿（`draft`）不计任何正式统计；`confirmed` 必须 `confirm=True` 且必须有分数。
- 改已确认分必须 `revision_reason`；`history` 记 `from/to/path/score/steps/rubric_version/谁/何时/理由`。
- 步骤扣分：`steps=[{step_index,label,deduction,note}]`，`r2_contract.step_deductions_consistent()`
  不一致 400 **不改库**（R2-INV-07）；扣分项与成绩行同期写入 `score_step_deductions`，撤回/失效时保留。
- 撤回：`state='unscored'`、`score=NULL`、`confirmed_at` 清空、历史保留（R2-INV-06）。
- 改标准/满分：`update_rubric(db, class_row, batch, user_id, question_no, rubric, rubric_version, full_score=None)`
  **必须给新 `rubric_version`**（空 / 未变都拒绝），保存后让该批次 `draft/confirmed` 全部 `invalidated`（R2-INV-05）。

### 1.4 失效链（派单 §四.3，动作清单来自 `r2_contract.apply_event()`）

| 事件 | 实现 | 落库动作 |
|---|---|---|
| `answer_content_changed` | `update_answer_content()` | 核验读成 `stale`、错因 `undecided`、评分 `invalidated`（原因 `answer_updated`） |
| `cause_retracted` | `retract_cause()` | 只写 `answer_checks.cause_state` 等错因列 + `cause_history`；错题退回；核验与评分不动 |
| `score_saved` | `save_score()` | `formal` 标记由 `confirmed` 决定；返回 `stats.formal_scores_only` / `stats.exclude_draft` |
| `score_retracted` | `retract_score()` | `answer_scores.retract` + `score_steps.keep_history` + `stats.recount` |
| `rubric_changed` | `update_rubric()` | `answer_scores.invalidate:rubric_changed` + `score_steps.keep_history` |

动作清单按**事件发生前**的四维快照计算（规则看到旧状态才给得出「该失效什么」）。

### 1.5 错题同步与知识点（R1 遗留 U2/K1/K2/K3）

- 错题行仍由 R1-16 幂等同步（`mistakes.answer_id` 唯一），本模块只补「知识点分类 + 依据」。
- `set_knowledge_point(db, class_row, user_id, answer_id, knowledge_point, basis="")` 写
  `mistakes.knowledge_points`（JSON 数组字符串）+ 备注留「依据 / 谁 / 何时」。
- **未分类 = `[]`**（不编造知识点名），备注标「知识点：未分类（缺依据，待教师补充）」。
- 撤回错因只退回「我方写的那条」（`source_type='作答核对'`），「作答分析」生成的那条不动（K2 口径统一）。
- 老结论不套新内容：所有读侧判据是 `answer_version = answers.fingerprint`（K3）。

### 1.6 AI 外发边界（派单 §四.6）

- 本模块无任何生成式模型调用；`local_decision(flow)` 恒 `allowed=False, code='ai_isolation'`。
- `guard_egress(flow, provider="", model="", fields=None)`：带 provider/model 或带
  `EGRESS_FORBIDDEN_FIELDS` 任一字段 → 403 `ai_isolation`。
- 判据来自 `r2_contract.AI_FLOWS`，**不读** `users.ai_individual_allowed`（测试里打开开关再试仍拒绝）。

### 3.4 覆盖率分母（与 `r2_contract.scoring_students` 同口径）

`grading.scoring_progress(db, class_row, batch)` 的 `eligible_students` = `r2_contract.scoring_students(config, records)`：
名单 × 应评分题**含未提交格子**全部参与，故「名单 10 人、2 人完全没交」时分母仍是 **10**。
断言 `8.10`（eligible=10、`denominator_source='roster'`）、`8.11`（分子只认完整成绩）、`8.12`（缺一题 complete=False）。

## 4. 风险与已知口径（不隐瞒）

1. **`rubric_version` 是批次级单个版本串**（契约 §3.1）。因此改任一题的评分标准/满分会让**该批次全部** `draft/confirmed`
   成绩失效（`6.8`）。理由：同批次一半按旧标准、一半按新标准的分不能一起算平均（§10 硬口径「不合并不可比」）。
   若 captain 后续要「按题失效」，需要在契约里给 `rubric_version` 加 per-question 维度（本任务不擅自改契约）。
2. **读侧与库侧的 rubric 版本判定会互相印证**：`_score_state()` 发现 `rubric_version` 与批次不一致时**报** `invalidated`
   （不是报 `confirmed`），配合 `update_rubric()` 的落库失效，保证「接口返回的状态就是库里的状态」。
3. **`effective_rows` 只加键、不改既有键语义**：新增 `knowledge_points`（list，未分类 `[]`）与 `occurred_on`（`answers.occurred_on`），
   既有键名与含义一字未动；`batch_rows` 仍按 `source` 只做标记不做过滤（正式/演示隔离由统计侧单点收口）。
4. **缺测/仅照片的「无需判断」是 R1 收口**：`answer_check._read_cause()` 会为无错步的作答补 `not_applicable`，
   本模块不自作主张改写，只在文档与断言里锁住「不落错题」这一后果。
5. **未覆盖**：`answer_check` 的追问保存（R1-06）只在错因确认时被顺带触发，本模块未单列断言；界面层（t4）不在本任务范围。

```python
from app import grading

# DesktopService 里加（class_row 用 service 现有的当前班级字典，与 answer_check 调用处同一个）
    # ---- R2-02 批量核验与评分（t3）----
    def grading_queue(self, batch="", scope="pending", answer_ids=None):
        """返回 list[dict]：answer_id/student_* /question_no/batch/occurred_on/source/

                                  answer_ids=answer_ids)

    def grading_progress(self, batch=""):
        """返回 dict：total/verified/pending/cause_decided/score_confirmed/complete_students…"""
        return grading.review_progress(self.db, self.class_row(), batch)

    def grading_batch_verify(self, batch="", scope="pending", answer_ids=None,
                             on_result=None, cancel_check=None):
        """逐条核验；on_result(result) 用于进度条刷新。返回汇总 dict（total/verified/skipped/
        failed/cancelled/remaining/failed_ids/results）。失败不抛异常。"""
        return grading.batch_verify(self.db, self.class_row(), self.user_id, batch,
                                    scope=scope, answer_ids=answer_ids,
                                    on_result=on_result, cancel_check=cancel_check)

    def grading_retry(self, failed_ids, on_result=None, cancel_check=None):
        return grading.retry_failed(self.db, self.class_row(), self.user_id, failed_ids,
                                    on_result=on_result, cancel_check=cancel_check)

    def grading_detail(self, answer_id, question_no=None):
        """单条批改视图：answer_checks 四维 + 候选取证 + 评分 + 步骤扣分 + 多图。"""
        view = grading.cause_candidates(self.db, self.class_row(), answer_id)
        return {"dimensions": grading.answer_dimensions(self.db, self.class_row(), answer_id),
                "score": grading.score_row(self.db, self.class_row(), answer_id, question_no),
                "candidates": view, "mistake": grading.mistake_of(self.db, self.class_row(), answer_id)}

    def grading_confirm_cause(self, answer_id, cause_label, cause_code="", basis_note="",
                              knowledge_point=""):
        return grading.confirm_cause(self.db, self.class_row(), self.user_id, answer_id,
                                     cause_code=cause_code, cause_label=cause_label,
                                     basis_note=basis_note, knowledge_point=knowledge_point)

    def grading_retract_cause(self, answer_id, reason=""):
        return grading.retract_cause(self.db, self.class_row(), self.user_id, answer_id, reason)

    def grading_save_score(self, answer_id, score, state="draft", steps=None,
                           revision_reason="", confirm=False, question_no=None):
        return grading.save_score(self.db, self.class_row(), self.user_id, answer_id, score,
                                  state=state, steps=steps, revision_reason=revision_reason,
                                  confirm=confirm, question_no=question_no)

    def grading_retract_score(self, answer_id, reason="", question_no=None):
        return grading.retract_score(self.db, self.class_row(), self.user_id, answer_id, reason,
                                     question_no)

    def grading_update_rubric(self, batch, question_no, text, rubric_version, full_score=None):
        return grading.update_rubric(self.db, self.class_row(), batch, self.user_id, question_no,
                                     {"text": text}, rubric_version, full_score)

    def grading_score_sheet(self, batch, question_no=""):
        return grading.score_sheet(self.db, self.class_row(), batch, question_no)
```

**错误约定**：上面所有方法失败一律抛 `grading.GradingError(message, status, code)`（中文 `message` 可直接显示）；
`grade_batch_verify` / `grading_retry` 不抛异常，逐条结果在返回体里。`status/code` 全量清单见 §5.3。

保留的 `status / code`（界面按 code 选文案，不要按 message 猜）：

| 场景 | status | code |
|---|---|---|
| 作答不存在 / 跨班 | 404 | `answer_not_found` |
| 版本不符（内容已更新） | 409 | `version_conflict` |
| 未核验就判错因 | 409 | `verify_required` |
| 判错因缺原因说明 | 400 | `cause_required` |
| 没有可撤回的错因/成绩 | 400 | `nothing_to_retract` |
| 分数非数值 / <0 / >满分 / >2 位小数 | 400 | `not_number` / `out_of_range` / `above_full` / `too_many_decimals` |
