# 页面说明｜作答核对与追问（第一轮 A1–A6）

本文是教师端网页的**页面说明与验收口径**，逐页写清「老师看到什么、能做什么、系统不该做什么」，供未参与开发的老师独立试用、也供走查时对照。

**范围**：只覆盖 `数智伴学_修改任务清单.md` A1–A6（教师电脑端网页）。B1–B7、C 不在本轮。
**依据**：`docs/作答核对_接口契约.md` §3、§4；数据见 `docs/模拟数据清单.md`。
**本文不宣称**五个页面已经连通，也不宣称任何一项已通过验收。界面是否跑通以 `docs/独立走查记录.md` 与实际浏览器走查为准。

---

## 0. 全页共同声明（必须能看见）

> **预置演示 · 不代表已实现通用定位**

- 本轮演示用的 `3(x-2)=12 → 3x-2=12` 这类首处错步，来自 `demo_answers.py` 的**预置条目**，`locate.source = "preset"`。
- **真实导入的作答走的是离线规则定位，这一项本轮已交付**：`src/app/equation_steps.py` 的 `locate()` 给出 `locate.source = "rule"`，含 `correct` / `first_bad` / `missing_steps` / `missing` / `out_of_scope` 五种 status；缺测与超范围给 `source = "none"`，超范围写「已转人工」。
- 但**规则定位 ≠ 通用定位**：它只覆盖**一元一次方程**这一限定题型，超出范围一律转人工、不硬判。所以界面上「预置演示 · 不代表已实现通用定位」这句话指的是**预置条目**这条路，不是否定规则定位已经存在——**预置（合成演示）与规则（真实导入）是两条路径，别混成一句**。
- 因此页面上必须同时出现两件事：数据来源标记（「合成演示数据」/「真实导入」）与定位来源标记（`preset` → 「预置演示」；`rule` → 规则定位）。合成数据缺「预置演示」标记、或把规则结果标成「预置」，走查都视为缺陷。
- 预置候选错因也只是条目，不是模型的判断结果；已审错因库检索属 B2，页面上要写「候选来自预置条目」。

## 1. 全局「模拟 / 真实」对照

| 页面元素 | 数据性质 | 界面上怎么说 |
| --- | --- | --- |
| 班级名、学生名 | 演示用合成班级/合成学生（或老师自己班里的真实名单） | 合成数据行标「合成演示数据」 |
| 作答正文（题目、学生原文、标准解） | 合成（案例 A/B/C/对照） | 同上 |
| 首处错步、划线、数学对照（合成演示四份） | 预置结果（`source=preset`） | 「预置演示 · 不代表已实现通用定位」 |
| 首处错步、划线、数学对照（真实导入的作答） | **规则定位（`source=rule`，`equation_steps.locate`，本轮已交付）**；缺测/超范围给 `source=none` + 「已转人工」 | 标「规则定位」；不标「预置演示」 |
| 候选错因、支持/反驳/待补 | 预置条目（`causes_source=preset`） | 「候选来自预置演示条目；已审错因库检索属于 B2，本轮未做」 |
| 追问问句 | 预置（案例 A）或老师现场输入的通用问句 | 预置的问句标「预置」 |
| 学生原话 | 演示为预置文本；老师手工输入时为真实记录 | 预置文本要能看出是演示 |
| 保存回执、队列、记录列表 | **真实写入本机数据库**（真功能） | 正常显示，不加「模拟」标记 |
| 载入/重置合成数据 | **真实写库与清理**（真功能） | 按钮旁注明「只影响合成数据」 |

## 2. A1｜课前总览（`#/class/{id}/check`）

**老师看到什么**

- 顶上一行：当前班级名 + 当前作业名（如「9月第2次作业」）。
- 三个数字：本次作业应交份数、待核对份数、已核对份数（缺测单独一个数，不混进「错」里）。
- 一句「下一份待核对」提示：`学生甲 · 第 1 题 · 去括号：是规则没掌握，还是这次漏写？`
- 一个主按钮：**查看待核对作答**。次级的「新建班级」「AI 设置」以文字链或小号按钮放在角落。
- 两种空状态有**不同**文案：
  - 一条作答都没有 → 「尚未导入作答」
  - 本次作业全部核对完 → 「本次作业已核对完」

**能做什么**

- 单击主按钮直达**下一份待核对作答**，不经过学生名单、不经过错题列表。
- 切换作业批次（多批次时）后，三个数字与「下一份」一起变。
- 老师想演示时，可以在这里载入/重置合成数据（入口旁写「合成演示数据，可随时重置」）。

**系统不该做什么**

- 不该把「待核对 0」和「没有作答」显示成同一张空表。
- 不该让主按钮点两次进两个不同地方：`待核对` 的数量与「查看下一份」必须用**同一个队列**（同一批次、按作答 id 升序、当前版本没有有效处理记录的第一条）。
- 不该在这里出现第二个同等分量的主按钮（每屏只突出一个主动作）。
- 不该把缺测算成「错」，也不该把缺测算进待核对的「错题数」。

## 3. A2｜作答核对 · 首处错步（`#/class/{id}/check/{answer_id}`）

**老师看到什么**

- 区块一：题目原文、题号、单元、数据来源标记（「合成演示数据」/「真实导入」）。
- 区块二：学生原文**逐行**列出，行号可见；不等价的那一行加**下划线**并有**文字标记「首处不等价」**；下方一行数学对照（等宽或衬线、字号大于记录编号），如「展开后应为 `3x-6`；括号外的 3 也要乘以 `-2`。」
- 区块三：完整标准解，**默认折叠**（`<details>` 或等效），老师要展开才看到。
- 定位来源标记：合成演示的作答标「预置演示 · 不代表已实现通用定位」；真实导入的作答由规则定位给出结果（`source=rule`），标「规则定位」，不要把规则结果标成「预置」。
- 案例 C 这类只有最终答案的：显示「缺少步骤」，不出现任何错行标记（规则定位给 `missing_steps`，缺测给 `missing`，两者都不标错）。
- 缺测的作答：显示「缺测」与原因，不标错（`source=none`）。
- 超出核验范围的作答：显示「已转人工」，原步骤照常完整显示，不判、不标（规则定位给 `out_of_scope`，`manual_note` 为「已转人工」）。

**能做什么**

- 阅读、折叠/展开标准解。
- 允许老师修改「观察到的错步」文本（默认填预置结果里的那一行），改完进入 A3 保存。
- 展开查看长作答的其余行（不因为首屏放不下就截断原文）。

**系统不该做什么**

- 不该从这一行**推断原因**：不出现「学生可能是……」「因为学生……」式文字。`reason_note` 固定为「这里只记录观察到的不等价，不推断学生为什么这样写。」
- 不该把正确作答标成错；不该为「缺少步骤」猜错在哪一行；不该为超出范围的题强行判对错。
- 不该把标准解铺在首屏把错步挤下去；错步与数学对照必须比记录编号醒目。
- 不该只靠颜色区分错步（投影上看不出颜色差异，必须有文字标记）。

## 4. A3｜作答核对 · 保存错步（同一页下半部）

**老师看到什么**

- 三个固定区块标题：**观察到的错步** / **可能原因** / **教师判断**。
- 「可能原因」里最多 3 条候选，每条都有**支持、反驳、待补**三类信息，逐条可见；没有候选时明确写「尚无已审错因库可用，保留待判断」。
- 「教师判断」区两个标签**分开显示**：处理进度（待核对 / 已核对）与原因判断（原因待判断 / 教师已判断）。
- 唯一主按钮：**保存错步，原因待判断**。

**能做什么**

- 只保存处理进度（原因待判断），课堂上再回来补；也可以选一条候选并填原因，保存为「教师已判断」。
- 采纳、改判（改判后旧原因不再作为当前结论，历史保留）、保留待判断三种动作都要在。
- 保存成功后在同处看到回执（见 A5）。
- 关闭页面重开后回来，仍显示原错步与「已核对 · 原因待判断」。

**系统不该做什么**

- 不该把「已核对」等同于「已判断原因」：两个标签不能合并成一个。
- 不该在老师点确认时对正确作答或缺测作答生成错题、写错误数。
- 不该把「预置候选」写成「系统判定」；选了一条也只是老师的判断。
- 保存失败时不该跳页、不该清空输入。

## 5. A4｜作答核对 · 当面追问

**老师看到什么**

- 一行提示：「可以这样问学生：你当时是怎么展开这个括号的？」
- 两个动作，只有两个：**记录学生回答**、**暂时跳过**。
- 没有「学生端页面」「发送给学生」之类入口。

**能做什么**

- 现场问一句，把学生原话敲进去，随本次核对一起保存，并挂在当前作答及其版本上。
- 「暂时跳过」只是跳过提问：不发请求、不跳页、不保存、不产生空回答记录。
- 跳过之后仍可以在保存了「原因待判断」的情况下，课堂后回到同一份补记原话。

**系统不该做什么**

- 不该把「暂时跳过」记成「学生拒答」。
- 不该因为没有追问就自动给出原因：没有新增依据时，原因仍是待判断。
- 不该要求学生账号、不该新建学生页面、不该以「先生成正式错题」为前提才能记追问。
- 不该在点「暂时跳过」时偷偷发一个空请求（走查时可用浏览器网络面板核对）。

## 6. A5｜保存结果 · 返回并找回（保存回执同屏于 `#/class/{id}/check/{answer_id}`；找回列表在 `#/class/{id}/check/records`）

> lead 2026-11-24 校订：原稿把 A5 的页面写成只对应 `#/class/{id}/check/records`，与契约 §4 的路由表不符。契约规定保存回执与「查看下一份」出现在**作答核对页保存后的同屏状态**，`check/records` 只承担「按原因待判断/教师已判断找回记录」。两者不是同一页，浏览器断言也分开做。

**老师看到什么**

- 保存成功同屏显示四样：学生原话、支持/削弱解释的依据、教师判断、**「已保存到：{班级} · {作业}」**。
- 一个按钮：**查看下一份**。
- 记录找回页：按「原因待判断 / 教师已判断 / 全部」筛选的列表，每行给作答人、题号、观察到的错步、保存时间、作业批次。
- 队列最后一份保存后，明确收尾提示（如「本次作业已核对完」）。

**能做什么**

- 「查看下一份」按固定顺序（同一作业、作答 id 升序）走；已保存的不再出现在待核对队列里，但仍能从记录页找回。
- 从记录页点进去改判或补记原话。
- 返回时保留原班级与作业，不回到首页。

**系统不该做什么**

- 不该在保存失败时把老师带走：必须留在当前页并保留全部输入。
- 不该让「列表」和「详情」说法不一致（同一份作答，列表显示的错步必须与详情一致）。
- 不该在最后一份保存后还给一个空白的「查看下一份」。
- 不该把已保存的记录从记录页弄丢（「该份退出待核对队列」≠「查不到」）。

## 7. A6｜视觉与投影

**老师看到什么**

- 1366×768 下首屏能看到**错步**和**主动作**，不需要横向滚动。
- 公式用等宽或衬线字体、字号大于记录编号。
- 错步同时有下划线和「首处不等价」文字标记。
- 每屏只有一个 `.btn.primary`。

**能做什么**

- 投影设备上直接演示，不必现场缩放浏览器；长作答可展开查看其余内容。

**系统不该做什么**

- 不该靠颜色区分错步；不该在一屏里放两个抢注意力的主按钮；不该为了塞下内容缩小公式字号。
