## 4. 横向溢出结论（1366×768 / 1920×1080）

### 4.1 判据（四条同时看）
1. `page.minimumSizeHint().width() > 窗口宽` → 页面最小宽度超过窗口，内容会被压缩/裁切（**真溢出**）；
2. 任一 `QScrollArea` 的 `horizontalScrollBar().maximum() > 0` → 页内水平滚动（**真溢出**）；
3. 任一可见子控件的右边缘越出直接父控件宽度（容差 2px）→ **控件超宽**；
4. `QTableWidget` 的 `horizontalScrollBar().maximum() > 0` → 表内横向滚动（数据表正常行为，
   **不算页面溢出**，单独记录数值）。

### 4.2 实测结果

| 页面 | 1366×768 判定 | 最小宽 | 页内滚动 hbar | 表内 hbar(max) | 1920×1080 判定 | 最小宽 | 页内滚动 hbar | 表内 hbar(max) |
|---|---|---|---|---|---|---|---|---|
| 登录 | 无横向溢出 | 361 | 0 | 0 | 无横向溢出 | 361 | 0 | 0 |
| 班级列表 | 无横向溢出 | 641 | 0 | 0 | 无横向溢出 | 641 | 0 | 0 |
| 学生名单 | 无横向溢出 | 365 | 0 | 0 | 无横向溢出 | 365 | 0 | 0 |
| 导入作答 | 无横向溢出 | 620 | 0 | 0 | 无横向溢出 | 620 | 0 | 0 |
| 作答分析 | 无横向溢出 | 439 | 0 | 0 | 无横向溢出 | 439 | 0 | 0 |
| 分析建议 | 无横向溢出 | 407 | 0 | 0 | 无横向溢出 | 407 | 0 | 0 |

补充：所有表格在两种尺寸下 `hbar_max = 0`（列宽由布局撑满视口；例如作答分析 7 列在
1366 宽下视口 1296、列合计 1296）。页内滚动区 `insightScroll` / `followupScroll` /
`aiSettingsScroll` / `mistakeDetailArea` 的 `hbar_max` 全为 0；`aiSettingsScroll` 在
1366 下内容 546 / 视口 1344，在 1920 下内容 546 / 视口 1898，**AI 设置新增内容不会挤爆**。
两个对话框的原生尺寸补拍同样无溢出：`分析建议-原生880x640`（最小宽 407，页内滚动 hbar 0，
表内 hbar 0）、`AI设置-原生780x700`（最小宽 405，`aiSettingsScroll` hbar 0）。

**结论**：1366×768 与 1920×1080 下现有 12 个页面**不存在水平滚动条，也不存在控件超宽**。
最宽的页面是「个人学情」（最小宽 696），在 1366 下仍有 670px 余量、在 1920 下余量 1224px。
新增「作答核对」页只要最小宽度 ≤ 1366 就不会把既有页面的横向布局带坏。

### 4.3 反向自证（证明这套判定不是「永远报无溢出」）

只用「都没溢出」当结论是不算证据的，所以额外做了三项对照（脚本 `selfcheck_overflow.py`）：

**A. 检测器能检出**：合成一个同时含「固定 600 宽父容器里塞 3000 宽子标签」「12 列 ×400 宽表格」
「内容最小宽 2600 的滚动区」的页面，实测输出：

```
判定：有横向溢出
  - 滚动区 QScrollArea[wideScroll] 出现水平滚动（范围 2000）
  - 控件超宽 2 处，最严重 QLabel[wideLabel] 越界 2409px
  表 QTableWidget[wideTable] hbar_max=11 列合计=4800 视口=570
→ 四条判据里的第 2、3、4 条都能正常触发。
```

**B. Qt 不允许把窗口压到最小宽度以下**：直接请求 300×300 时窗口会停在最小宽度上
（登录 361×371、班级列表 641×300、导入作答 620×350、作答分析 439×300、分析建议 407×336）。
所以「把窗口调小」根本造不出横向溢出——溢出的真实条件是「页面最小宽度 > 目标窗口宽」。

**C. 小屏边界（附加观察，非本次要求尺寸）**：请求 1024×768 与 800×600 时 12 个页面全部缩得到，
没有一页被最小宽度顶住（最大最小宽 696 < 800）。即连 800×600 都不会出现横向溢出。
