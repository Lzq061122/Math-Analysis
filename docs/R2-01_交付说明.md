### 1.2 包格式与 CSV 字段

```
assignment.zip
├── answers.csv                 # 必须放在根目录，有且只有一个；UTF-8 / UTF-8 BOM / GB18030
└── images/                     # 图片只收 .jpg/.jpeg/.png，路径写包内相对路径
    ├── S01-1-1.png
    └── S01-1-2.png
```

CSV = R1 的 12 列（`记录编号,学生姓名,学校编号,题号,题目内容,单元,标准解法,学生步骤,来源批次,作答日期,缺测,缺测原因`）**+ 新增可选列 `图片路径`**（多图用 `;` / `；` / `|` 分隔）。
**不填图片路径 = 纯文字导入**，行为与 R1 完全一致。

### 1.3 限制在「解压过程中」的实际执行点（`src/app/answer_import_zip.py`）

| 限制 | 代码位置 | 判定时机 |
|---|---|---|
| ZIP 100 MB | `read_package()` 第 **210** 行 `if len(raw) > MAX_ZIP_BYTES:` | 打开压缩包**之前**（连 ZipFile 都不构造） |
| 文件数 2000 | 第 **218** 行 `if len(infos) > MAX_FILES:` | 遍历中央目录时，**不读任何条目内容** |
| 加密条目 | 第 **229** 行 `if info.flag_bits & 0x1:` | 读取前按标志位拒绝（不是读到一半才报） |
| 非法路径（绝对/`..`/盘符） | 第 **231** 行 `if _is_unsafe_name(name):`（`_is_unsafe_name` 第 179 行） | 每个条目名进来就先判，**从不拼接落盘路径** |
| 解压后合计 300 MB | 第 **236** 行 `if total > MAX_UNCOMPRESSED_BYTES:` | 累加 `info.file_size` 的过程中即时超限即拒（不解压） |
| 嵌套压缩包 | 第 **240** 行 `if ext in NESTED_ARCHIVE_EXTS:` | 按条目扩展名拒绝 |
| CSV 不在根目录 | 第 **244** 行 | 同一次遍历 |
| 图片不在 `images/` | 第 **248** 行 `if not name.startswith(IMAGES_DIR):` | 同一次遍历 |
| 单图 10 MB | 第 **250** 行 `if int(info.file_size or 0) > MAX_IMAGE_BYTES:` | 声明尺寸即判；`Package.read_image()` 里再核一次实际字节（防声明与实际不符） |
| 不支持的文件类型 | 第 **257** 行 `raise _zip_error("unsupported_file", name)` | 白名单之外一律整包拒绝 |
| 缺/多 CSV | 第 **260/262** 行 | 遍历结束后 |

**整包拒绝时零写入、零落盘**（测试 6.3–6.19 每条都断言 `answers` 行数与 `uploads` 文件集合不变）。

### 1.4 六类预览分类与「未提交/缺测/内容不足」的落地

| 分类 | 判据 | 可导入 |
|---|---|---|
| `valid` 有效 | 内容合规、非缺测 | 是 |
| `missing` 缺测 | `answers.missing=1`（老师明确标缺测） | 是 |
| `duplicate` 重复 | 同编号 + 指纹相同 | 跳过 |
| `conflict` 冲突 | 同编号 + 指纹不同 | 需勾「覆盖」 |
| `unmatched` 未匹配学生 | 班级里没有该学生/编号对不上/同名多人 | 否（需选学生或补名单） |
| `file_error` 文件异常 | 行内容不合规、声明的图片类型不支持 | 否 |

**仅照片作答**（有图、无学生步骤、未明确标缺测）按契约判成 `insufficient`（内容不足），**不是缺测**：
R1 的 `answers.parse()` 会把「没写步骤」自动判成缺测，本模块保留「缺测」列原文（`_split_image_cells` 第三返回值），只对「老师没明确标缺测」的行改判，并在库里写 `missing=0`（测试 3.9 / 5.3 断言）。
**缺图**（声明了但包里没有）只给提示、不阻断导入（测试 5.1 / 5.4）。

### 1.5 覆盖 = R2-INV-01

同编号异内容、老师勾选覆盖时：
1. 更新 `answers` 行（内容与 `fingerprint` 一起换）；
2. 调 `r2_contract.apply_event("answer_content_changed", …)` 取动作清单 → 旧追问标 `answer_updated`、既有评分置 `invalidated`（`answer_scores.state='invalidated'` + `invalidated_reason='answer_updated'`）；
3. 旧图片行删除、旧图片文件在 COMMIT 之后删（回滚时文件还在），本次新图重新落盘；
4. 把 `invalidated`（规则 id / 动作 / 追问数 / 评分数）回给界面与 R2-02。
测试：4.6–4.9。

### 1.6 异常回滚

`commit()` 全程一个 `db.tx()`；**任何异常**（含 `MISTAKE_FAULT` 注入的 `zip_commit`）→ 事务回滚 + 删除本次新落盘的全部图片（`except BaseException` 分支），批次登记也在同一事务里，所以「库不留半条、uploads 不留孤儿、批次不留空壳」三者同时成立。
测试：7.1–7.4。
