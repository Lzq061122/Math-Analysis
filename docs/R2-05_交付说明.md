## 3. 关键口径（会进集成验收，写在这里作为单一依据）

1. **版本是唯一的「当前」判据**：推荐、提示、任务、PDF 一律按记录下来的版本号取正文；任务里存
   `resource_versions`（key→version）。资源出新版本 / 停用后，引用旧版本的推荐、提示与任务只打
   「依据已变，待复核」（`r2_contract.apply_event('resource_version_changed', ...)` → 任务
   `review_state='needs_review'`），**不静默换版本、不删旧引用**（R2-INV-08）。
2. **任务依据变化只打标记**：`mark_task_review()` 走 `apply_event('task_basis_changed')`，
   只写 `review_state`；`status` 不动、不自动改派、不自动完成（R2-INV-09）。
3. **双审核 + 权限**：数学正确性 / 教学适切性分别记录（审核人/时间/意见/发布版本）；两项均 `pass`
   且审核人是**两个不同账号**才可发布；发布只能由这一版的审核人执行，其它账号（含未登录、不存在账号）
   一律拒绝，且拒绝发生在写库之前。改内容 = 新版本 = **重回待审核**，旧版本的「通过」不顺延。
4. **未审 / 停用 / 合成不进正式推荐**：只认 `status='published'` + 当前版本 `state='published'` +
   `source` 不含「合成测试」。草稿、待审核、停用、合成资源一律不出现（合成资源即使被发布也不出现）。
5. **完整解析必须在独立尝试之后**：只认 `hint_usages.independent_before_solution`；教师提前看答案
   （`independent_attempt=0` 却给了完整解析）直接拒绝、不写库。
6. **真实学生作答不外发**：本任务全部路径都是本地 SQLite 检索，不读 `users.ai_individual_allowed`，
   `r2_contract.egress_decision('teaching_resource_match')` 恒 `False`。
7. **不改 R1**：`answer_followups` / `answer_checks` / `mistakes` 等 R1 表结构与语义一个字未改；
   四维口径不重写，一律调 `grading` 的只读函数。

### 实现层的两个自觉选择（便于 review）

- **发布权 = 审核人**：`users` 表没有角色列（R2-00 未加，也不该由 R2-05 加），所以「发布权限账号校验」
  落成「必须是完成这一版审核的审核人之一」——审核人对内容负过责，发布只是把已审版本置为已发布；
  第三个老师、未登录账号、不存在的账号都会被拒绝并有明确 code（`not_reviewer` / `no_account` /
  `unknown_account`）。要改成「管理员角色」需要 `db.py` 加列，由 captain 定，不在本任务内私改。
- **`source` 含「合成测试」即隔离**：与 R1 的 `source='合成演示'` 判据同源（按内容判、不按批名猜），
  合成资源可以照常走完送审/发布流程，但永远不会进入正式推荐——这样隔离断言不会因为「没发布」而蒙对。
