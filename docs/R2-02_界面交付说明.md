## 1. 实现内容与入口

### 1.1 三个页签（`GradingWindow`）

| 页签 | 面板 | 做什么 |
|---|---|---|
| 批量核验 | `BatchVerifyPanel` | 选作业批次 / 全部待核验 / 批次内全部 / 指定记录 → 逐条核验、进度条、逐条状态表、结果汇总、运行日志、取消未处理、重试失败、双击打开单条 |
| 单条批改与评分 | `AnswerReviewPanel` | ① 题目与标准解法（含本题评分标准与该题版本）② 学生原始步骤 + 多图查看 ③ 数学核验结论 + 首个错误步骤原文证据 + 候选错因 + 教师判断 + 知识点 ④ 教师评分（满分/分数/步骤扣分/一致性提示/草稿/确认/撤回/修改理由） |
| 评分进度 | `ScoreProgressPanel` | 按题看应评/已确认/草稿/未评/已失效/平均分/得分率 + 批次级评分覆盖率（分母=应参与评分学生数） |

四块分区标题固定为「① 题目与标准解法」「② 学生原始步骤与关联图片」「③ 数学核验结论 · 错因判断 · 知识点」
「④ 教师评分（满分以批次配置为准）」，一眼能看出「三者分区展示」（派单 §4.2）。

### 1.2 交互约定（与 R1 `CheckWindow` 同一套习惯）

1. **先看进度再逐条改**：批量核验每处理一条就把结果写进明细与日志；`on_result` 回调刷新进度条。
2. **失败留在原页**：单条失败不弹窗打断整批，汇总里记「失败 n」，`重试失败` 只重跑这些 id；失败码与中文原因逐条写进日志。
3. **取消只停未处理**：`取消未处理` 置位取消标志，当前这条会保存完，剩余进 `remaining`，界面提示「未处理的 n 条保持原状」。
4. **错误提示逐字给**：后端 `GradingError.message` 原样显示，再按 `status/code` 补一句「下一步」
   （`ui_grading.GRADING_ERROR_HINTS`；本模块没有的码回落到 `ui.CHECK_ERROR_HINTS`，机制与 CheckWindow 一致）。

### 1.3 后端适配层（两条路，都不绕归属闸门）

- `ServiceGradingBackend`：**默认路径**。窗格只认 12 个 `grading_*` + `owned_class_row` 的真实方法名（与 `service.py`
  逐字一致，见 `b45c611`/`61a58d8`），所有读写都经 service（`class_id` 为第一参数，归属校验在 service 入口）。
  写操作一个不落：`grading_batch_verify / grading_retry / grading_confirm_cause / grading_retract_cause /
  grading_save_score / grading_retract_score / grading_update_rubric`，`grading_update_rubric` 第五个参数传**标准正文字符串**。
- `GradingBackend`：直连 `app.grading` 的适配层（测试、独立窗口、无 service 的入口用），行为与 service 路径同源。

`service.grading_detail` 返回 `{dimensions, score, candidates, mistake}`；界面还需要作答正文/图片/本题标准，
因此 `ServiceGradingBackend.detail()` 在这四份之上用同一个 `db` 按 `class_id` 收口补三条只读字段
（`answers` 行、`answer_images` 行、`r2_contract.question_rubric`），不另写业务判断。

### 1.4 题级评分标准编辑

「①②区间」里的 `保存本题标准` 只改**当前这条作答的题号**：正文 + 新版本号（+ 可选新满分），
调 `grading_update_rubric(class_id, batch, question_no, text, rubric_version, full_score)`；
成功后提示「本题标准已更新为版本 X；只有本题旧成绩失效（n 条），其它题不受影响」，
不给新版本号会被后端 400 `rubric_version_unchanged`，界面显示原因 + 下一步提示。

### 1.5 多图查看

`ImagePreviewDialog`：上一张 / 下一张 / 「第 n / m 张」，越界按钮自动禁用；文件读不出来时在画布上写明文件名，
不弹窗、不崩溃。`②` 区每条图片一个按钮（`图片 1..n`），另有「查看全部图片」。

## 4. 风险与未覆盖（不隐瞒）

1. **入口与菜单由 captain 接**：本模块不改 `ui.py`。构造签名就是 captain 期望的
   `GradingWindow(self.service, class_row, parent=self)`；传 service 时自动用 `ServiceGradingBackend`
   （`hasattr(service, "grading_queue")` 探测，探测名与 `service.py` 实现名逐字一致，测试 9.1 锁住）。
2. **删除/越权**：越权 class_id 由 service 入口抛 `ApiError 404「班级不存在」`，界面按错误显示（不当成空表）；
   本模块不自己再判一次归属，避免两套判据。
3. **线程与取消**：真机取消按钮在主线程置位，核验循环在后台线程逐条检查；测试里主线程被 `wait()` 占住，
   所以用 `Qt.DirectConnection` 在核验线程内立即置位来复现同一语义（测试注释已写明）。窗口关闭时会取消并 `wait(3000)`。
4. **不弹模态框**：所有结果与错误都写在页内标签/日志里，只有「删除、撤回」这类操作在后续版本若需要二次确认再加；
   当前实现保证 offscreen 测试与脚本化操作都不会被弹窗卡住。
5. **图片路径**：`answer_images.file_path` 是绝对路径就直接用，否则按 `uploads` 目录拼；文件缺失时查看器显示
   「图片文件读不出来：<文件名>」，不崩溃也不静默（7.6 只覆盖「没有图片」这一档）。
6. **未覆盖**：`answer_check` 的追问（R1-06）没有界面入口（R1 核对页已有）；评分建议（「无依据留空」）在界面上
   表现为「分数留空 + 存草稿」，未做自动建议值（R2-02 不做生成式建议）。

## 5. 接线片段（captain 已接 `service.py`，这里只补 ui.py 菜单）

```python
# src/desktop/ui.py（captain 接；grading 不改这个文件）
from desktop.ui_grading import GradingWindow

# 与 open_teaching() 同一写法：未选班级停用，点击提示「先在列表里点一个班级」
def open_grading_window(self):
    if not self.current_class:
        QMessageBox.information(self, "提示", "先在列表里点一个班级。")
        return
    self._grading_window = GradingWindow(self.service, self.current_class, parent=self)
    self._grading_window.show()
```

`GradingWindow` 的对外属性（测试与后续 R2-06 验收可复用）：
`window.verify_panel` / `window.review_panel` / `window.score_panel` / `window.last_error` /
`window.open_answer(answer_id)` / `window.refresh_all(answer_id=None)`。
`BatchVerifyPanel.run_verify_sync()` 是同步入口（无事件循环时用），`start()/cancel()/retry()` 是按钮对应方法。
