   - 变异体 1：`equation_steps` 的 `hint_text` 改成 `None` → 案例 A 的「`hint_text` 逐字在该行内」断言不再成立（实测变异输出 `["first_bad", null, {"start": 2, "end": 4}]`）；
   - 变异体 2：不再比较相邻两行 → 案例 A 从 `first_bad` 变 `correct`（实测 `["correct", null]`）；
   - 变异体 3：`_force_undecided` 恒 `False` → 缺测/正确/只有答案的「原因强制回 undecided」断言不再成立（实测 `[false, false, false]`）；
   - 变异体 4：`_batch_counts` 的 `checked` 恒 0（**带真实库副本**）→ 队列待核对数从 `[0,3,all_checked]` 变 `[3,0,has_pending]`。
   每个变异体都先断言「补丁命中唯一位置」（防止补丁没打上却以为验过），再对比真实实现的值。
2. **同一表达式在状态变化时必须翻转**：版本失效前后 `pending` 1→2、`checked` 1→0；10 条造数里「直接数作答=10」而「checked=9」。
3. **缺口不写成通过**：四条界面缺口由 `未通过（缺口）` 行单列，既不计入 125 条通过断言，也不被静默忽略；每条都带测量值（top/disabled/按钮列表/接口状态）。
4. **没有为了全绿动产品代码**：`src/**` 未改（见文首）；发现的问题交给 lead，由 T10 修。
