### 1.1 接口（R2-06 与界面复用）

```python
REPORT_VERSION = "R2-04.1"; PURPOSES = ("存档", "教学研究", "家长沟通", "其他")

build_class_report(db, class_id, batch="", filters=None, today="", generated_at="",
                   user=None, purpose="存档", limit=6) -> dict      # 唯一读库点
build_student_report(db, class_id, student_id, ...) -> dict        # 同上（含证据链/建议/历史）
preview_lines(report) -> list[str]        # 预览（与 PDF 同序同数）
render_pdf(report) -> bytes               # 纯函数：只吃 report，不查库
export_pdf(report, path, db_file=None, purpose=None) -> dict       # 写文件 +（可选）记历史
history_path / load_history / save_history(db_file)                # 导出历史（库文件同目录 JSON，原子写）
representative_mistakes(snapshot, limit=6, per_knowledge=2)        # 代表性错题约束
```

**快照是唯一输入**（captain 要求 + §6.2 原文）：`build_*_report()` 只读一次库，把
`r2_stats.class_snapshot/student_snapshot`、`mistake_evidence`、`saved_advice`、`student_history`、
班级建议全部装进 report；`preview_lines/render_pdf/export_pdf` **不再查库**，
所以「预览后改数据再导出」得到的 PDF 仍对应预览时的快照（验收 5.1–5.6）。

### 1.2 报告内容（§6.1 两栏表逐项落点）

| 班级报告 | 个人报告 |
|---|---|
| 1 班级与统计范围（班级/批次/业务日期/筛选原文/记录数/生成时间/数据版本/满分合计） | 1 学生与统计范围 |
| 2 作答及审核概况（8 项计数） | 2 个人作答及审核概况 |
| 3 有效成绩统计（平均分/覆盖率/完整成绩/应参与评分）+ 3.1 各题得分率（含已评份数）+ 3.2 完整成绩分布图 | 3 有效个人成绩 + 3.1 各题得分率 |
| 4 知识点错误分布（图 + 明细表）、4.2 未分类错题说明 | 4 知识点错误分布（图 + 明细表） |
| 5 错因分布（图 + 明细表） | 5 主要错因（图） |
| 6 班级共性问题（按涉及学生数排序，频次辅助） | 6 重点辅导问题（复用原版近期加权排序） |
| 7 代表性错题（默认高频、每类≤2、总数≤6，**不列学生列**） | 7 对应错题及证据 + 7.1 证据链（题干/标准解法/学生步骤/教师判断/错步原文） |
| 8 已保存教学建议（无则「暂无」） | 8 已保存个人辅导建议（过期标「待复核」） |
| — | 9 已安排的针对性练习（**R2-05 接口预留**，当前空态「暂无已安排的针对性练习」） |

规则：缺分母用「暂无/无法计算」（不画 0）；`demo_batch` 整批标「合成演示、不计入正式统计」；
代表性错题与共性问题只用快照明细，不另查库；个人报告的「证据链」限定本人作答（验收 2.1–2.3、5.2）。

### 1.3 版面与工具链

- **排版只用 `src/app/pdf_canvas.py`**（R2-05b 的纯标准库 A4 画布）：中文 TrueType 子集 + `/ToUnicode`、
  自动分页、长表格跨页重画表头、页脚「第 n / 共 m 页」、条形/柱状图带数值标签、空态框。
  两个解释器都没有 reportlab/fpdf/weasyprint，派单要求离线运行，所以不自造第二套 PDF 底层。
- 图表：知识点/错因横向条形、完整成绩分布纵向柱状（数值标签是真文本，可被 `extract_text` 读回）。
- 权限：`_require_access()` 校验 `classes.user_id`（越权 404 不泄露存在性）；学生还要校验属于该班。

### 1.4 导出历史（R2-04 fix / t10 起入库）

- 位置：**`app.db` 的 `r2_report_exports` 表**（R2-00.5），随备份/恢复一起走；最多 50 条（写入侧裁，最新在前）。
- 字段（对外返回结构不变）：`at / user / user_id / kind / title / purpose / batch / filters / path / bytes / sha256 / data_version`
  （表内另有 `class_id/student_id/scope/created_at`；`user` 由读时 join `users.username` 补回，`title`/`data_version` 是导出那一刻的快照值）。
- 侧车文件 `r2_report_exports.json` 只保留 `history_path()` 兼容与**一次性迁移**入口：首次写入前把旧 JSON 搬进表并改名 `.imported`（不删，留证据；同一账号已有行则整批跳过，防翻倍）。
- 详解见 `docs/R2-04_导出历史入库说明.md`（含「备份→换机恢复后历史仍在」的断言与证据）。
