## 3. 怎么保证"不是假绿"

这一轮最费力的不是写功能，是让证据可信。评审三轮共提出 15 项问题（R-01…R-10、N-01…N-03、O-1、O-2），全部关闭，**没有为了让测试变绿而删改任何既有断言**（删除的是失效的死代码）。

| 问题 | 性质 | 处理 |
|---|---|---|
| R-01 | **证据绑在已不存在的文件上** | 冻结字节：每次日志头写 `app.js/styles.css` 等文件的 sha256；E2E 换端口由三方各自独立复跑 |
| R-02 | 选择器写错导致 A5 阶段整段中止 | 改选择器（不改语义），A5 三阶段恢复 |
| R-03② | **假闭合**：号称"关闭"，实际只是让假阳性检测器不再被调用，代码原样留着 | 整段删除 + 删掉重复定义，账目与代码一致 |
| R-04 | **按钮说谎**：`decided` 态主按钮写着"原因待判断"却提交 `decided` | 标签随状态变；新增次要按钮「改为原因待判断」，补齐回头路 |
| O-2 | **空断言**：`13.1.10b` 只要页面上出现过这个数字就过，把网格数字 +1 仍 PASS | 改为逐格取 `k/v` 比对，并加页内变异自证 |

变异自证（改坏必须变红，本轮共 5 组）：`_force_undecided→False` 红 3 条、队列排序反向红 5 条、去掉版本校验红 3 条、对照句退化简式红 3 条、`demo_answers.reset` 变异红 3 条。

E2E 计数演进：174 → 175（新增的 1 条正是 O-2 修正后的逐格断言）。**对外一律引用 175/175。**
