## 2. 学生（这里的甲/乙/丙/丁是**示意**，不是界面上的实际显示名）

| 指代 | 姓名（仅空班时才会真的建出这个人） | 备注字段 | 用途 |
| --- | --- | --- | --- |

| 学生乙 | 学生乙 | `合成演示数据 · 可重置` | 案例 B（证据足够，可不追问） |
| 学生丙 | 学生丙 | `合成演示数据 · 可重置` | 案例 C（只有最终答案） |

**实际上会挂在谁名下（以 `demo/seed` 实际行为为准）**：`seed()` 在**已经有学生的班级**里，会把四份合成作答按记录编号顺序挂到**班级现有学生**上（`student_ids` 给了就用给的，没给就用班级现有在用学生），**不会**新建上面这四个名字；因此在演示班级里，界面上看到的是老师自己班的学生名（本次走查看到的是「林一诺 / 周子航」），不是「学生甲」。**只有空班**（一个学生都没有）才会补建上表这四位，并在 `seeded.students_created` 里报数。这是有意为之：演示要的是「老师看到的是自己班的人」，所以不要为了对上名字去改 `seed` 逻辑；看数据请按「案例 A/B/C/对照」认，不按姓名认。
**重置时怎么处理**：`reset` 只清理「备注是 `合成演示数据 · 可重置`」且「已经没有任何作答、错题」的学生。真实名单里带同名学生不会被删（备注不同），真实学生名下一旦有作答也不会被删。
**如果名单不足 4 人**：作答按传入/现有学生的顺序**循环分配**，同一个学生可能带两份以上示例作答（演示足够了；真实使用时不会这样，因为班级人数远多于 4）。

## 3. 逐条作答

### 3.1 案例 A｜`DEMO-A-01`（学生甲，题号 1）

**合成演示数据 · 案例 A · 定位状态 `first_bad`（预置）**

- 题目：`3(x-2)=12`
- 标准解（界面默认折叠）：`3(x-2)=12；3x-6=12；3x=18；x=6`
- 学生原文（逐行）：

  | 行 | 原文 | 角色 | 标记 |
  | --- | --- | --- | --- |
  | 1 | `3(x-2)=12` | 题干 | — |
  | 2 | `3x-2=12` | 学生 | **首处不等价**，划线 `-2` |
  | 3 | `x=14/3` | 学生 | — |

- 预置定位结果（契约 §2 键名，`source="preset"`）：
  - `first_bad_index = 1`，`first_bad_text = "3x-2=12"`
  - `underline = {"start": 2, "end": 4}`（**逐字取子串**：`"3x-2=12"[2:4] == "-2"`）
  - `hint_text = "-2"`
  - `contrast.expected = "3x-6"`，`contrast.actual = "-2"`，
    `contrast.note = "展开后应为 3x-6；括号外的 3 也要乘以 -2。"`
  - `reason_note = "这里只记录观察到的不等价，不推断学生为什么这样写。"`
- 预置候选（3 条，最多 3 条；`selected` 只是演示默认高亮，不等于系统已判定）：

  | 代码 | 候选标签 | 支持证据 | 反驳／削弱依据 | 待补证据 |
  | --- | --- | --- | --- | --- |
  | `E-DIST-01` | 只把系数乘以括号里的第一项（常数项没乘） | ① 学生这一行只把 3 乘给了 `x`，常数项停在 `-2`，写成 `3x-2` 而不是 `3x-6`。② 预置学生原话「2 只要乘 y 就好了」：同一套规则用到 `2(y-4)` 上，`-4` 也会被留在括号外。 | 这条只与观察到的写法一致；同一份作答里没有第二处漏乘，还不能排除这次是一次性漏写。 | 还没有学生独立重做 `2(y-4)` 或完整口述去括号规则的记录。 |
  | `E-DIST-02` | 括号外系数与括号内符号的处理偏差 | 学生原话提到括号里的 `-4`「不用管」，可能把符号判断和乘法分开处理。 | ① 本题括号外是正数 3，正系数去括号不会发生符号翻转，与这条的典型表现不符。② 若是符号规则偏差，`-2(x-3)` 一类题会稳定出错；现有记录里没有这种稳定表现。 | 需要 `2(y-4)`、`(y-4)×2` 之类的独立作答或口述作为依据。 |
  | `E-WRITE-01` | 书写遗漏（抄写或跳步时漏写） | 下一步 `x=14/3` 正好由 `3x-2=12` 推出，过程自洽，像是把「×(-2)」抄漏了。 | 同一份作答的题干一行 `3(x-2)=12` 抄写无误，没有第二处漏写可以相互印证。 | 还没有本人确认是否抄错的记录。 |

- 预置问句：`你当时是怎么展开这个括号的？`
- 预置学生原话：`2 只要乘 y 就好了。`（演示里点「记录学生回答」后出现在同屏回执上；这一句是预置文本，不是现场采集）
- 预期界面行为：
  1. 首屏看到第 2 行加下划线 + 文字标记「首处不等价」，不是只变颜色；
  2. 三个候选同时列出支持／反驳／待补，**没有一条被写成「已确认原因」**；
  3. 点「记录学生回答」才出现原话；点「暂时跳过」不发请求、不跳页、不产生回答记录；
  4. 点「保存错步，原因待判断」→ 回执写清班级与作业，状态显示「已核对 · 原因待判断」；
  5. 统计上：原题错误数 +1，已确认错因数 +0（两者口径不同）。

### 3.2 案例 B｜`DEMO-B-01`（学生乙，题号 1）

**合成演示数据 · 案例 B · 定位状态 `first_bad`（预置）**

- 题目：`5x-3=2x+6`
- 标准解：`5x-3=2x+6；5x-2x=6+3；3x=9；x=3`
- 学生原文：`5x-3=2x+6` → `5x-2x=6-3`（**首处不等价**，整行划线）→ `x=1`
- 预置定位结果（与规则引擎 `equation_steps.locate` 逐字段一致，由不变式守住）：
  - `first_bad_index = 1`，`first_bad_text = "5x-2x=6-3"`
  - `underline = {"start": 0, "end": 9}`，`hint_text = "5x-2x=6-3"`（**整行**）
    为什么是整行：这一步是「移项没有变号」，错在整条等式的移项方向，无法定位到单个字符；
    整行划线比指认某个 token 更诚实，也与规则引擎能给到的结论一致。
  - `contrast.expected = "5x-3=2x+6"`（上一行原文），`contrast.actual = "5x-2x=6-3"`（学生这一行原文），
    `contrast.note = "这两行不等价：上一行是 5x-3=2x+6，学生这一行是 5x-2x=6-3。"`
    注意：对照句两端**逐字取自原文**，只出现真正写下的两行，不出现「移项之后才算得出来」的拼写。
- 预置候选：`E-TRANS-01` 移项没有变号
  - 支持：`5x-3=2x+6` 移项后应为 `5x-2x=6+3`，学生写成 `5x-2x=6-3`，常数项符号没跟着移。
  - 反驳：若只是这一处笔误，后面 `x=1` 会与 `6-3` 的结果自洽；现象上仍分不清是规则错还是笔误。
  - 待补：证据足够时可当场问一句确认；本轮不追问也允许保留待判断。
- 预置问句：`这条等式是你把哪一项移到另一边了？`
- 预期界面行为：可以不追问、直接保存待判断；追问入口仍然可用（不因为没有候选就藏掉追问）。

### 3.3 案例 C｜`DEMO-C-01`（学生丙，题号 2）

**合成演示数据 · 案例 C · 定位状态 `missing_steps`（预置）**

- 题目：`4(x-1)=8`
- 标准解：`4(x-1)=8；x-1=2；x=3`
- 学生原文：只有一行 `x=1`
- 预置定位结果：`status = "missing_steps"`，`first_bad_index = None`，`first_bad_text = None`，
  `manual_note = "学生只写了最终答案，缺少中间步骤：这里只提示补录，不判断错在哪一行。"`
- 预置候选：无（`causes_source = "none"`）
- 预置问句：`能把这道题中间的两步补上吗？`
- 预期界面行为：
  1. 显示「缺少步骤」，**不标错行、不指错因、不给候选**；
  2. 仍可以保存处理进度（`已核对 · 原因待判断`）；
  3. 保存后**不生成错题、不计原题错误数**；
  4. 如果界面出现「学生可能是……」一类推断，即为缺陷。

### 3.4 对照｜`DEMO-OK-01`（学生丁，题号 3）

**合成演示数据 · 对照 · 定位状态 `correct`（预置）**

- 题目：`2(x+3)=10`
- 标准解：`2(x+3)=10；2x+6=10；2x=4；x=2`
- 学生原文：`2(x+3)=10` → `2x+6=10` → `2x=4` → `x=2`（全程等价）

## 4. 幂等与重置（演示可以反复做）

| 操作 | 行为 | 证据字段 |
| --- | --- | --- |
| `seed` 第一次 | 写入 4 份合成作答（必要时补建合成学生） | `seeded.answers = 4`，`seeded.synthetic = true` |
| `seed` 第二次（同班级） | 一行都不新增 | `seeded.answers = 0`，`seeded.skipped_existing = 4` |
| 判重口径 | 同班级内 `record_key` + `source` 相同即视为已写入 | 契约 §5 |
| 与真实导入撞号 | **不覆盖**真实记录，跳过并报 `skipped_conflict` | `seeded.skipped_conflict` |
| `reset` | 只删 `source='合成演示'` 的作答，及其 `answer_checks` / `answer_followups` / `answer_reviews` | `deleted.answers / followups / checks / reviews` |
| `reset` 后真实数据 | 一条不动，并给数字 | `kept.imported_answers` |
| `reset` 后合成数据 | 归零 | `kept.synthetic_answers = 0` |

重置**不删**：真实导入的作答、真实学生的名单、错题表里任何记录、上传的图片。合成学生只有在「带合成备注」且「已无任何作答与错题」时才被清掉。

### 5.1 防漂移不变式（预置值必须等于规则引擎）

预置定位是手写常量，规则引擎是代码。两边各改各的，就会出现「同一道题，演示页说一套、自动定位说另一套」，
老师看到的解释会随数据来源变化。所以 `demo_answers.py` 里放了一条不变式，把预置值钉在规则输出上：

```powershell
C:\Python314\python.exe -c "import sys; sys.path.insert(0,'src'); from app import demo_answers as D; print(D.verify_preset_matches_rules()); D.assert_preset_matches_rules()"
```

- `verify_preset_matches_rules()`：对 `build()` 里每一份带 `locate` 的作答，用
  `equation_steps.locate(question_text, standard_solution, student_steps, missing=...)` 重算，
  逐字段比对 `status / first_bad_index / first_bad_text / underline / hint_text / contrast.expected / contrast.actual / contrast.note`；
  返回差异列表（空列表＝全等），每项带 `record_key / field / preset / rule`。
- `assert_preset_matches_rules()`：不一致就抛 `AssertionError` 并把每处差异打出来。
- 只比这 8 个字段；`source` 不比——预置恒为 `preset`，规则引擎恒为 `rule`，这是两者**应该**不同的地方。
- 当前状态：四份合成作答全部逐字段一致。若以后有人只改了一边，上面的命令立刻报差异。
- `build()` 本身**不**调用规则引擎：合成数据必须能在没有规则引擎时照常演示，只有自检才去比对。
